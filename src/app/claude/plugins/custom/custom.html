Свой плагин

Свой плагин собирают, когда настройку — скиллы, субагентов, хуки, MCP-серверы — нужно отдать другим людям или поставить в много проектов. Для себя в одном проекте хватит обычных файлов в .claude/. В приложении Claude плагин можно сделать вообще без файлов, попросив Claude. Из чего состоит плагин — на странице Что такое плагин.

В приложении Claude

  • Create with Claude — Customize → Plugins → Add → Create with Claude. Опишите задачу так же, как объяснили бы коллеге, ответьте на вопросы (например, какие коннекторы нужны). Claude напишет скиллы и команды и покажет результат карточкой — нажмите Save plugin.
  • Create a plugin — то же через форму и редактор, когда вы уже знаете, что писать в каждом скилле.
  • Готовая папка — Add → Upload plugin, ZIP-архив, внутри которого есть .claude-plugin/plugin.json.

Плагин сохраняется в аккаунт и работает в чате, в Cowork и в Claude Code. Проверьте его на настоящем запросе и подключите его коннекторы. Раздать — только на Team и Enterprise: Share даёт плагин конкретным коллегам (только для чтения, выключенным, пока они его не включат), Publish to org отправляет в библиотеку организации — сразу или через проверку владельцем, как он настроил.

В Claude Code: первый плагин

Минимальный плагин — манифест и один скилл:

.claude-plugin/plugin.json:

skills/release-notes/SKILL.md — обычный скилл:

Проверить и запустить, ничего не устанавливая:

  • В .claude-plugin/ только plugin.json. Папки skills/, agents/, hooks/ и файл .mcp.json кладут в корень плагина — изнутри .claude-plugin/ они не загрузятся.
  • name — единственное обязательное поле, без пробелов. Становится префиксом всех скиллов и агентов: /my-plugin:release-notes.
  • version — пока вы его не поменяете, установившие плагин из маркетплейса обновлений не получат. Не указали — версией считается коммит.
  • Пути к своим файлам в хуках и MCP-серверах пишут через ${CLAUDE_PLUGIN_ROOT}: куда плагин установится, заранее неизвестно.
  • CLAUDE.md в плагине не читается. Общие инструкции оформляют скиллом.

Быстрый старт

Заготовку можно не писать руками:

Плагин plugin-dev добавляет скиллы и агентов для написания компонентов: Claude спросит, что нужно, создаст файлы и прогонит проверку.

Из готовой настройки проекта

Если скиллы, агенты и хуки уже лежат в .claude/, их не переписывают, а копируют в плагин:

  • Имена поменяются — /deploy станет /my-plugin:deploy, агент reviewer — my-plugin:reviewer.
  • Удалите оригиналы из .claude/, когда проверите плагин. Иначе хуки сработают дважды: у них нет префикса, и копия из плагина не заменит исходный хук.

Как раздать

СпособКому подходитКак
Папка или ZIPПаре коллег, без обновленийОни запускают claude --plugin-dir ./my-plugin.zip или загружают архив в приложение через Upload plugin
Свой маркетплейсКоманде, с версиями и обновлениямиРепозиторий с marketplace.json — см. Маркетплейсы
Share и Publish to orgОрганизации в приложении (Team, Enterprise)Customize → Plugins → карточка плагина
Каталог AnthropicВсем пользователям ClaudeПубличный репозиторий GitHub и заявка на проверку. После неё плагин появится в Discover, а в Claude Code придёт через аккаунт

Проверьте, что увидят пользователи приложения. Чат загружает из плагина только скиллы, команды и удалённые MCP-серверы, Cowork — ещё агентов и хуки. Плагин с папкой bin/ приложение не установит вовсе: утилиты кладут, например, в scripts/ и вызывают из хуков. Полная таблица — в Что такое плагин.
