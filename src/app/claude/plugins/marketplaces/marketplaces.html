Маркетплейсы

Маркетплейс — каталог плагинов: git-репозиторий, папка или URL с файлом .claude-plugin/marketplace.json, где перечислено, какие плагины есть и откуда их брать. Это не магазин и не сервер, а просто список. Каталог добавляют один раз, а дальше ставят из него плагины по имени плагин@маркетплейс и получают обновления. Как ставить плагины — на странице Установка.

Какие бывают

КаталогЧто внутриКак получить
claude-plugins-officialПлагины Anthropic (commit-commands, code-review, LSP-плагины) и партнёровClaude Code добавляет сам при первом запуске

Каталог Anthropic в приложенииПлагины для чата и Cowork, прошедшие проверкуCustomize → Plugins → Discover на Pro, Max, Team и Enterprise
СторонниеКаталоги компаний, авторов, вашей командыДобавить вручную. Anthropic их не проверяет

Посмотреть официальный каталог без Claude Code можно на claude.com/marketplace. Старые инструкции советуют /plugin marketplace add anthropics/claude-code — это демо-каталог claude-code-plugins, его плагины почти все есть в официальном. Ставьте их оттуда, чтобы не держать по две копии.

Подключить каталог

В Claude Code:

  • Имя после @ — поле name из marketplace.json, а не имя репозитория. Claude Code печатает его при добавлении.
  • Приватный репозиторий клонируется с вашими git-доступами (SSH-ключ, gh auth login). Паролей Claude Code не спрашивает: нет доступа — команда просто не пройдёт.
  • Автообновление у сторонних каталогов выключено. Включают в /plugin → Marketplaces → Enable auto-update.

В приложении Claude — Customize → Plugins → Add → Add marketplace: URL или owner/repo. Подходят GitHub и GitHub Enterprise, а также публичные репозитории GitLab и Bitbucket. Для приватного репозитория GitHub приложение попросит подключить аккаунт GitHub. Можно добавить до 25 каталогов. Обновить вручную — Check for updates, для github.com есть ещё Sync automatically.

Свой каталог

Нужен, когда команда должна ставить ваши плагины по имени и получать обновления. Это репозиторий с файлом каталога и папками плагинов:

  • Обязательные поля — name, owner и plugins, у каждого плагина — name и source.
  • source — путь от корня каталога (без ..), отдельный репозиторий (github), подпапка монорепозитория (git-subdir). Ещё бывают url, npm и zip-архив.
  • Имя плагина в каталоге и в его plugin.json должно совпадать, иначе установка по имени не найдёт плагин.
  • Официальные имена вроде claude-plugins-official заняты за Anthropic — такой каталог Claude Code не добавит.

Проверить и поставить у себя, до публикации:

Потом репозиторий пушат на git-хостинг, и коллеги добавляют его как обычно: /plugin marketplace add your-org/team-plugins. Как собрать сам плагин — в Своём плагине.

Раздать команде

Чтобы каталог и плагины появлялись у всех, кто работает в репозитории, их прописывают в .claude/settings.json проекта и коммитят:

  • Как срабатывает — коллега открывает проект, соглашается доверять папке, и каталог добавляется сам. Плагин, который лежит внутри репозитория каталога, тоже подключится сам. Плагин из отдельного репозитория каждому придётся один раз поставить: claude plugin install deploy-helper@team-tools --scope project.
  • Вся компания — администратор задаёт те же ключи в управляемых настройках (Organization settings → Claude Code → Managed settings или MDM). Отключить их пользователь не сможет, а ключ strictKnownMarketplaces запрещает все каталоги, кроме перечисленных.
  • Приложение на Team и Enterprise — владелец подключает приватный репозиторий в Organization settings → Plugins & skills и для каждого плагина выбирает режим: недоступен, доступен для установки, установлен по умолчанию или обязателен. До Claude Code такие плагины доходят через аккаунт.
