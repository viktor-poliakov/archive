Свой скилл

Свой скилл — ваш порядок работы, записанный один раз: шаги, формат результата, шаблоны и скрипты. Проще всего его получить так: решить задачу вместе с Claude, а потом попросить оформить сделанное скиллом. Что такое скилл и из чего он состоит — на странице Что такое скилл, куда его положить и как вызвать — в Подключении и вызове.

Когда стоит писать

  • Объясняете одно и то же второй-третий раз — формат отчёта, правила оформления, порядок релиза.
  • У задачи есть шаги или шаблон, и результат должен каждый раз выглядеть одинаково.
  • Нужен скрипт, который надёжнее, чем код, написанный заново: проверка, конвертация, выгрузка.
  • Не нужен для общих правил проекта — это CLAUDE.md. А если задачу надо делать в отдельном контексте и вернуть только отчёт, нужен субагент.

Как создать

Попросить Claude — работает и в приложении, и в Claude Code. Лучше всего сразу после того, как задача решена: всё нужное уже есть в разговоре.

  • В приложении Claude задаст уточняющие вопросы, возьмёт встроенный скилл skill-creator, соберёт файл скилла и предложит его сохранить. Скилл появится в Customize → Skills. Править его можно там же: выделите текст в файле → Edit with Claude.
  • В Cowork на Mac (Pro, Max, Team) скилл можно записать с экрана: + → Record a skill, проделайте задачу, Claude предложит скилл по записи.
  • В Claude Code Claude сам создаст папку в .claude/skills/ или ~/.claude/skills/ — скажите, куда.

Написать руками — создать папку с SKILL.md. В Claude Code её сразу кладут в ~/.claude/skills/ или в .claude/skills/ проекта. В приложение загружают ZIP-архив через Customize → Skills → + → Create skill → Upload a skill:

Скилл с аргументом, который запускается только вручную — /fix-issue 1234:

  • $ARGUMENTS — всё, что написано после имени скилла. Отдельные аргументы — $0, $1…
  • ${CLAUDE_SKILL_DIR} — путь к папке скилла. Через него вызывают скрипты скилла из любой рабочей папки.
  • Подстановки и !`команда` работают только в Claude Code.

Поля frontmatter в Claude Code

ПолеЧто задаёт
nameИмя и команда /name. Без поля — имя папки
descriptionЧто делает скилл и когда его брать. По нему Claude решает, нужен ли скилл
argument-hintПодсказка к аргументам в меню /
disable-model-invocationtrue — только ручной вызов
user-invocablefalse — только Claude, в меню / не видно
allowed-toolsИнструменты, которые можно без вопросов, пока скилл выполняется. Остальные не запрещает
model, effortМодель и уровень усилий на этот ход
context: forkВыполнить скилл в субагенте. Какой именно — в поле agent
pathsGlob-маски: Claude сам берёт скилл, только когда работает с подходящими файлами
hooksХуки, которые включаются вместе со скиллом

В приложении и API полей меньше: name, description, license, compatibility, metadata и allowed-tools. С любым другим полем скилл не загрузится, а Claude Code неизвестные поля молча пропускает.

Как написать, чтобы работало

  • description — что и когда, в третьем лице, со словами, которыми задачу формулируют на самом деле: «отчёт», «дифф», «презентация». Коротко: в приложении лимит 200 символов.
  • SKILL.md — до 500 строк. Подробности выносите в отдельные файлы и ссылайтесь на них прямо из SKILL.md, без цепочек «файл ссылается на файл».
  • Не объясняйте очевидное. Что такое PDF или git, Claude знает. Пишите то, чего он знать не может: ваши правила, шаблоны, исключения.
  • Главное — в начале. После компактизации от скилла остаются только первые 5 тыс. токенов.
  • Повторяемое — скриптом, и прямо напишите, что его нужно запустить, а не прочитать.
  • Никаких ключей и паролей в файлах. Доступ к сервисам — через коннекторы и MCP.
  • Правило, которое нельзя нарушать, лучше вынести в хук: скилл Claude может и не выполнить, а хук срабатывает всегда.

Скилл не срабатывает? Добавьте в description слова из ваших запросов или вызовите его вручную. В приложении видно, взял ли Claude скилл, в его рассуждениях. В Claude Code проверьте, что скилл есть в /skills, а битый frontmatter найдёт claude plugin validate .claude/skills. Поделиться скиллом: в проекте — закоммитить .claude/skills/, в приложении — Share на Team и Enterprise, шире — упаковать в плагин.
