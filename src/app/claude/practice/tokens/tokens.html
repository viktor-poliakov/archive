Экономия токенов

С каждым сообщением модель получает весь разговор: инструкции, CLAUDE.md, прочитанные файлы, вывод команд. Поэтому платите вы — лимитом подписки или деньгами по API — прежде всего за размер контекста, а не за длину вопроса. Экономия сводится к двум вещам: держать контекст маленьким и подбирать модель под задачу. Как устроены лимиты — в Тарифах и лимитах.

Где смотреть расход

  • /usage — расход и лимиты. На подписке там же доля скиллов, субагентов и MCP-серверов и готовые советы вроде «урежьте CLAUDE.md — 49k токенов на запрос». Клавиша f применит то, что Claude Code может исправить сам.
  • /context — чем занят контекст прямо сейчас.
  • В приложении — Settings → Usage.

Контекст — главная статья расхода

  • Новая задача — /clear. Это бесплатно, а старый контекст иначе оплачивается в каждом следующем сообщении.
  • /compact — сам по себе большой запрос: Claude читает весь разговор, чтобы его сжать. Если продолжение не нужно, дешевле /clear.
  • Перерыв дороже, чем кажется. Кэш живёт ограниченное время, и после долгой паузы первое сообщение заново обрабатывает весь контекст. То же делает каждое срабатывание /loop в открытой сессии.
  • Конкретная задача — «добавь проверку ввода в login из auth.ts» вместо «улучши код»: Claude прочитает три файла, а не сотню.

Подробнее о сжатии и о том, что занимает контекст, — в Контексте и компактизации.

Модель и effort

  • Sonnet справляется с большинством задач кода и дешевле Opus. Opus оставьте для архитектуры и сложных многошаговых задач. Переключение на Opus действует и на субагентов, которые наследуют модель сессии.
  • Effort — размышления оплачиваются как выходные токены. У моделей 5.5 и Fable их не выключить, поэтому рычаг один — уровень effort. Подробнее — в Моделях и выборе.
  • Быстрый режим (/fast) стоит вдвое дороже — включайте, только когда важна скорость.

Что грузится в каждую сессию

  • CLAUDE.md — до 200 строк, только то, что нужно всегда. Инструкции для редких дел (ревью PR, миграции) вынесите в скиллы: они загружаются, только когда нужны.
  • MCP-серверы — неиспользуемые отключите в /mcp. Где есть CLI (gh, aws, gcloud), он экономнее сервера.
  • Плагин code intelligence — один «переход к определению» вместо поиска и чтения нескольких файлов-кандидатов.
  • Фильтр через хук — вместо 10 000 строк лога Claude получит только строки с ERROR: сотни токенов вместо десятков тысяч.

Субагенты и параллельная работа

Шумную работу — прогон тестов, чтение логов и документации — отдайте субагенту: длинный вывод останется в его контексте, вам вернётся итог. Его запросы тоже тратят лимит, поэтому дайте ему модель попроще:

  • Параллельные сессии — у каждой свой контекст, а лимит один на всех.
  • Agent teams тратят в разы больше обычной сессии: каждый напарник — отдельный Claude со своим контекстом. Держите команду маленькой и закрывайте напарников, когда их работа сделана.

В приложении Claude

  • Новая тема — новый чат. Длинная переписка дорожает с каждым сообщением.
  • Документы, к которым возвращаетесь, — в проект: там они кэшируются и при повторном использовании тратят меньше лимита.
  • Вопросы — одним сообщением и сразу с контекстом, а не по одному с уточнениями.
  • Выключите лишнее — веб-поиск, Research, коннекторы: инструменты расходуют много токенов. При большом числе коннекторов переключите Tool access на On demand.

В Claude API

  • Prompt caching — повторяющееся начало запроса (системный промпт, инструменты, документы) читается из кэша примерно за 10% цены.
  • Message Batches API — скидка 50% за асинхронную обработку: результат приходит в течение суток.
  • Модель и effort под задачу — классификацию и извлечение данных обычно тянет Haiku.
  • max_tokens — потолок длины ответа, чтобы случайно не оплатить простыню текста.
