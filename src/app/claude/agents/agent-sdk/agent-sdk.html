Agent SDK

Claude Agent SDK — Claude Code в виде библиотеки для TypeScript и Python. Это тот же агентный цикл и те же встроенные инструменты: чтение и правка файлов, Bash, поиск, веб. Есть разрешения, сессии, хуки и субагенты. Вы передаёте задачу и настройки, а цикл SDK ведёт сам. Работает агент в вашем процессе и на ваших серверах.

Типичные задачи для SDK: бот, который чинит упавшие тесты в CI; ревью пул-реквестов; агент поддержки со своими инструментами для заказов и тикетов; разбор логов с заведением задачи в трекере.

Установка

  • Claude Code ставить не нужно — его движок идёт внутри пакета.
  • Ключ берётся из окружения. Файл .env SDK сам не читает — загрузите его, например, через dotenv.
  • Bedrock, Google Cloud, Foundry — вместо ключа задайте CLAUDE_CODE_USE_BEDROCK=1, CLAUDE_CODE_USE_VERTEX=1 или CLAUDE_CODE_USE_FOUNDRY=1 и учётные данные облака.
  • Только API-ключ — вход через аккаунт claude.ai и лимиты подписки в своём продукте использовать нельзя, если Anthropic не одобрила это отдельно.

Первый агент

Агент, который ищет и чинит ошибки в файле. Сохраните как agent.ts и запустите npx tsx agent.ts (для await на верхнем уровне в package.json нужен "type": "module"):

  • query() запускает цикл и возвращает асинхронный поток сообщений: рассуждения, вызовы инструментов, их результаты.
  • Сообщение result — последнее, с итогом, стоимостью (total_cost_usd) и session_id.
  • Если задача упала с ошибкой, query() выдаёт result с ошибкой, а потом бросает исключение — оборачивайте цикл в try/catch.

В Python всё то же самое: query() и ClaudeAgentOptions, опции в snake_case.

Свои инструменты

Инструмент — функция с описанием и схемой аргументов на Zod. SDK заворачивает её в MCP-сервер, который работает прямо в вашем процессе:

  • Имя для allowedTools — mcp__<сервер>__<инструмент>. Все инструменты сервера — mcp__shop__*.
  • Ошибку возвращайте с isError: true и понятным текстом — Claude прочитает его и попробует по-другому. Исключение из обработчика цикл не роняет, но Claude увидит голое сообщение об ошибке.
  • Готовые внешние MCP-серверы (GitHub, БД, браузер) подключаются через тот же mcpServers.

Субагенты, хуки и лимиты

Субагентов задают в коде, в опции agents: поля те же, что во frontmatter своего субагента. Хуки — обычные функции, которые срабатывают до или после вызова инструмента:

  • Agent в allowedTools — иначе каждый запуск субагента будет ждать разрешения.
  • Субагенты из .claude/agents/ тоже подхватываются. При совпадении имени побеждает тот, что задан в коде.
  • Хук на PreToolUse может запретить вызов: причину отказа Claude получит как результат инструмента.

Сессии

Каждый query() по умолчанию — новый разговор. Чтобы продолжить прошлый, сохраните session_id из сообщения result и передайте его в resume:

  • continue: true — продолжить последнюю сессию в этой папке, без ID.
  • forkSession: true вместе с resume — новая сессия с копией истории. Оригинал не меняется.
  • Сессия — это только разговор, а не файлы. Правки, которые агент уже сделал, остаются на диске.

Перед продом

  • Лимиты — всегда задавайте maxTurns и maxBudgetUsd: агент сам решает, сколько шагов делать и сколько субагентов звать.
  • Минимум прав — в allowedTools только то, что нужно задаче. bypassPermissions — только в изолированном контейнере.
  • Несколько клиентов — у каждого своя файловая система, settingSources: [] и CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 в env, иначе агент подхватит чужие настройки и память.
  • Название — свой продукт нельзя называть «Claude Code». Можно «Claude Agent» или «<Имя> Powered by Claude».
