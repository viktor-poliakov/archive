Свой субагент

Свой субагент — Markdown-файл, в котором описан помощник: когда его звать, какие инструменты ему можно, на какой модели работать и что делать. Написали один раз — дальше Claude сам зовёт его, когда задача подходит. Если файл лежит в git, субагент есть у всей команды. Как субагенты работают и как их вызывать — на странице Субагенты.

Когда стоит заводить

  • Роль повторяется — ревью, прогон тестов, миграции БД, проверка доступности вёрстки.
  • Нужны ограничения — например, ревьюер, который физически не может править код.
  • Рутину хочется удешевить — перевести её на Haiku или Sonnet.
  • Не нужен для разовой задачи — проще попросить словами. А если инструкция должна работать в основном разговоре, а не в отдельном контексте, — это скилл.

Как создать

Проще всего — попросить Claude. Он напишет файл сам, останется проверить frontmatter:

Или написать файл руками. Вверху frontmatter с настройками, ниже — системный промпт субагента:

Где лежитДля кого
.claude/agents/Текущий проект. Кладут в git — субагент есть у всей команды
~/.claude/agents/Вы, во всех проектах
Папка agents/ плагинаВезде, где включён плагин
Флаг --agentsТолько текущая сессия, файл не нужен
  • Совпали имена — побеждает флаг --agents, потом проект, потом личные, потом плагин.
  • Правки подхватываются сами за несколько секунд. Перезапуск нужен, только если папки agents до старта сессии не было.

Поля frontmatter

ПолеЧто задаёт
nameИмя, обязательное. Без двоеточий
descriptionКогда звать субагента, обязательное. По нему Claude решает, отдавать ли задачу
toolsРазрешённые инструменты. Без поля — все, что есть у сессии
disallowedToolsЗапрещённые инструменты, например Write, Edit
modelhaiku, sonnet, opus, fable или inherit — как у сессии
permissionModeСвой режим разрешений, например plan или acceptEdits
isolationworktree — работать в отдельной копии репозитория, чтобы правки не мешали вашим
backgroundtrue — всегда работать в фоне
memoryСвоя память между сессиями: project, user или local
skills, mcpServers, hooksСкиллы, MCP-серверы и хуки только для этого субагента
maxTurnsСколько шагов субагент может сделать

Опечатку в поле никто не заметит. Неизвестные поля Claude Code молча пропускает. Если субагент ведёт себя не так, как написано во frontmatter, сначала проверьте названия полей.

Как написать, чтобы работало

  • description — коротко и конкретно. Описания всех субагентов постоянно лежат в контексте, а когда вместе они переходят за 15 000 токенов, Claude Code предупреждает об этом при старте. Подробности переносите в промпт: он загружается, только когда субагент запущен.
  • «Используй сразу после…» в описании подталкивает Claude звать субагента без напоминаний.
  • В промпте — роль, шаги и формат отчёта. В основной разговор вернётся только отчёт, поэтому заранее скажите, что в нём должно быть.
  • Минимум инструментов — без Edit и Write субагент не испортит код, даже если захочет.

Идеи и нужные поля

СубагентКак настроить
Ревьюерtools: Read, Grep, Glob, Bash — без правки файлов
Дешёвый поиск по кодуСвой субагент с именем Explore и model: haiku — заменяет встроенный
Массовый рефакторингisolation: worktree — правки в отдельной копии, вы потом смотрите diff
Аналитик БДtools: Bash и хук PreToolUse, который пропускает только SELECT
Знаток проектаmemory: project — заметки копятся в .claude/agent-memory/<name>/

Проверить субагента — попросите «используй test-runner, чтобы прогнать тесты» или напишите @agent-test-runner. У субагентов из плагинов поля hooks, mcpServers и permissionMode не работают; если они нужны, скопируйте файл в .claude/agents/. В приложении Claude своих субагентов нет: повторяющиеся инструкции там оформляют скиллами или проектами.
