Задачи по расписанию

Claude Code умеет сам запускать работу по времени — три способа: /loop внутри открытой сессии, локальные задачи Claude Desktop и облачные задачи, которые работают, даже когда компьютер выключен. Типичные задачи: следить за деплоем, ревьюить PR по утрам, разбирать свежие задачи, проверять зависимости. Расписание задач в чате и Cowork описано на странице Задачи и расписание.

Коротко: облако — для надёжной регулярной работы с репозиторием, Desktop — когда нужны локальные файлы и программы, /loop — чтобы приглядеть за чем-то, пока вы работаете.

/loop в сессии

  • С интервалом (5m, 2h, 1d или «every 2 hours») — запуск по фиксированному расписанию. Секунды округляются до минуты.
  • Без интервала — Claude после каждого прохода сам выбирает паузу от минуты до часа: чаще, пока идёт сборка, реже, когда всё затихло.
  • Скилл — можно передать вместо текста, если Claude разрешено вызывать его самостоятельно.
  • Голый /loop — встроенное задание: доделать начатое, разобрать комментарии и упавший CI в PR текущей ветки, а если всё чисто — поискать баги. Своё задание по умолчанию пишут в .claude/loop.md.

Разовые напоминания и управление — обычными словами:

  • Остановить — цикл без интервала: Esc, пока он ждёт; с интервалом — попросить Claude отменить его.
  • Работает, только пока сессия открыта и Claude не занят: задание выполняется между вашими сообщениями. Пропущенные запуски не догоняются.
  • Повторяющиеся задачи удаляются через 7 дней, в сессии их не больше 50. Время — локальное. Запуск сдвигается, чтобы сессии не били в API одновременно: у ежечасных и ежедневных задач — до 30 минут.
  • Выключить планировщик совсем — переменная CLAUDE_CODE_DISABLE_CRON=1.

Локальные задачи Claude Desktop

Каждый запуск — новая сессия Claude Code в выбранной папке, с доступом к вашим файлам, программам и MCP-серверам. Проще всего попросить Claude прямо в сессии на вкладке Code:

Вручную: Code → Scheduled → New task → Set up manually. Задайте имя и инструкции, в Advanced settings включите Only on this computer и выберите папку, затем расписание (Hourly, Daily, Weekdays, Weekly), режим разрешений и модель.

  • Компьютер спал — при пробуждении Desktop сделает один запуск за последний пропущенный срок, остальные пропустит. Если время важно, напишите в задании, например: «если уже после 17:00, только сводку».
  • Разрешения — в режиме Manual запуск встанет и будет ждать вашего ответа. Сделайте первый запуск кнопкой Run now и на каждый запрос выберите «always allow»: следующие запуски пройдут без вопросов.
  • Изоляция — по умолчанию задача работает с папкой как есть, включая незакоммиченные правки. Галочка Worktree в форме Edit даёт каждому запуску отдельный git worktree.
  • Где лежит — инструкции задачи хранятся в ~/.claude/scheduled-tasks/<имя>/SKILL.md, их можно править руками.

Облачные задачи

Облачная задача — сохранённая настройка Claude Code: промпт, модель, репозитории, облачное окружение и коннекторы. Каждый запуск — новая облачная сессия: репозиторий клонируется заново, правки уходят в ветки claude/…. Раньше функция называлась routines. Она в research preview и доступна на тарифах Pro, Max, Team и Enterprise.

Создать можно на claude.ai/code/routines, на странице Scheduled в Claude Desktop или командой /schedule в Claude Code — она расспросит о деталях и сохранит задачу:

ТриггерКогда запускается
ScheduleПо расписанию, не чаще раза в час, или один раз в заданное время
APIПо POST-запросу на адрес задачи с её токеном — из мониторинга, деплоя, своих скриптов
GitHub eventНа событие репозитория: открытие или мёрж PR, релиз, с фильтрами по ветке, автору, меткам

Триггеры совмещаются: одно и то же ревью может идти каждую ночь и на каждый новый PR. Вызов через API — URL и токен берут в настройках задачи на сайте:

  • Задача действует от вашего имени: коммиты идут от вашего GitHub-аккаунта, сообщения в Slack — от вашего. Все коннекторы включены по умолчанию, лишние уберите.
  • Разрешения — запуск идёт в auto mode. Если что-то требует подтверждения, сессия ждёт вашего ответа.
  • Зелёный статус значит только, что сессия запустилась и завершилась. Сделано ли дело — смотрите в самом запуске, в History.
  • Текст из API (text) Claude получает как недоверенные данные. Чтобы он действовал по нему, так и напишите в промпте задачи: «разбери алерт из тела запроса».
  • Лимиты — запуски тратят лимит подписки, как обычные сессии. /schedule работает только при входе через аккаунт claude.ai, не по ключу API.

Другие варианты

  • В CI — workflow с триггером schedule, см. GitHub Actions.
  • На своём сервере — обычный cron и headless-режим. С --bare нужен ANTHROPIC_API_KEY в окружении cron.
