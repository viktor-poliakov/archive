GitHub Actions

Claude Code GitHub Action (anthropics/claude-code-action@v1) запускает Claude Code в workflow репозитория. Напишите @claude в комментарии к задаче или пул-реквесту — Claude разберётся в коде, внесёт правки, запушит коммиты и ответит в том же треде. Или дайте ему задание, и он выполнит его сам на любом событии GitHub: открытии PR, релизе, по cron.

Для чего

  • Задача → пул-реквест — «@claude сделай по описанию», и через несколько минут готов PR.
  • Правка по комментарию — починить ошибку, переименовать, дописать тест прямо из ревью.
  • Вопросы по коду — как устроен модуль, где лучше сделать изменение.
  • Ревью каждого PR — со своими правилами и комментариями к строкам.
  • Регулярные задачи — ежедневная сводка, разбор свежих задач, проверка зависимостей.

Установка

Быстро — из Claude Code в папке репозитория:

Команда ставит Claude GitHub App, сохраняет ключ в секреты репозитория, пушит ветку с workflow и открывает в браузере готовый пул-реквест. Смёржите его — и @claude заработает. Нужны права администратора репозитория и установленный gh. Работает только с github.com.

Вручную — если Claude Code локально нет или нужен полный контроль:

  • 1. Установите Claude GitHub App на репозиторий или всю организацию.
  • 2. Добавьте секрет репозитория — ключ API или токен подписки (см. таблицу ниже).
  • 3. Скопируйте examples/claude.yml из репозитория action в .github/workflows/.
СекретОткудаЧем платите
ANTHROPIC_API_KEYClaude ConsoleОплата API по токенам
CLAUDE_CODE_OAUTH_TOKENclaude setup-token на своей машинеЛимиты подписки Pro, Max, Team или Enterprise

В workflow секрет передают во вход с тем же смыслом: anthropic_api_key или claude_code_oauth_token. Токен подписки привязан к человеку, который его создал, поэтому для общего секрета организации берите ключ API.

Ответы на @claude

Если у action нет входа prompt, он ждёт упоминания @claude в комментарии, ревью или тексте новой задачи. Это и есть стандартный claude.yml:

  • Ответ — комментарием в том же треде, Claude обновляет его по ходу работы.
  • Кто может позвать — только пользователи с правом записи в репозиторий. Ботов action отклоняет, чтобы они не запускали Claude по кругу.
  • @claude — отдельным словом: /claude и @claude-bot не сработают. Другое слово задают входом trigger_phrase.

Запуск по событию

С входом prompt Claude работает без упоминания, на любом событии workflow. В prompt можно передать и вызов скилла. Пример: ревью каждого PR плагином code-review с комментариями к строкам:

По расписанию — через обычный schedule. Без --allowedTools у Claude нет ни Bash, ни GitHub API, поэтому нужные инструменты разрешают явно:

  • Куда пишется результат — в лог workflow. В PR или задачу Claude напишет, только если это сказано в промпте и у него есть инструмент для комментариев.
  • Расписание GitHub запускает только из ветки по умолчанию, а в публичных репозиториях отключает после 60 дней без активности.
  • PR из форков в публичных репозиториях секретов не получают, так что ревью для них не запустится.

В корне репозитория стоит держать CLAUDE.md со стилем кода и правилами ревью: Claude читает его на каждом запуске.

Расходы и безопасность

  • Платите дважды — минутами GitHub Actions и токенами Claude. Ограничивайте --max-turns в claude_args, timeout-minutes у job и параллельность через concurrency.
  • Ключи — только в GitHub Secrets, никогда в файлах репозитория. Права workflow выдавайте минимальные, правки Claude смотрите перед мёржем.
  • CI не запускается на коммитах Claude — проверьте, не передан ли github_token со стандартным GITHUB_TOKEN: коммиты с ним GitHub не триггерит. Уберите вход, и action будет работать от имени Claude GitHub App.

Рядом. Action построен на Agent SDK, как и headless-режим, — флаги и правила разрешений там те же. Если нужно просто автоматическое ревью каждого PR без своего workflow, у Anthropic есть отдельный продукт Code Review. Для GitLab есть аналогичная интеграция Claude Code GitLab CI/CD. Старые workflow на @beta переводят на @v1: direct_prompt → prompt, вход mode удалить, флаги — в claude_args.
