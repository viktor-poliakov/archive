Настройки settings.json

settings.json — JSON-файлы, в которых настраивается сам Claude Code: модель по умолчанию, разрешения, переменные окружения, хуки, плагины. В отличие от CLAUDE.md это не текст для модели, а конфигурация, которую исполняет сама программа: модель не может её «не послушаться».

Где лежат

ФайлДля когоВ git
~/.claude/settings.jsonТолько вы, все проекты—
.claude/settings.jsonВся команда, этот проектДа
.claude/settings.local.jsonТолько вы, этот проектНет: Claude Code сам добавляет его в исключения git, а созданный вручную — внесите в .gitignore
Managed (managed-settings.json, политика из консоли claude.ai)Вся организация, ставит администратор—
  • Приоритет — managed → флаг --settings → settings.local.json → settings.json проекта → пользовательский. Если ключ задан в нескольких файлах, побеждает тот, что выше.
  • Списки складываются — permissions.allow и другие массивы не перезаписываются, а объединяются из всех файлов.
  • Сразу файлов нет — установка их не создаёт. Пользовательский появится при первой правке через /config, локальный — при первом ответе «да, больше не спрашивать». Проектный создайте сами.
  • Windows — ~/.claude означает %USERPROFILE%\.claude.

Как поменять

  • /config — короткое меню личных опций, сохраняет их в ~/.claude/settings.json. Есть только в терминале; в десктопе и VS Code правьте файл или настройки самого приложения.
  • Правка файла — всё остальное. JSON строгий: комментарий или висящая запятая — ошибка, о которой Claude Code скажет при запуске. Строка $schema включает в редакторе автодополнение и проверку ключей.
  • Когда применяется — почти всё подхватывается на лету, без перезапуска. Главные исключения — model и effortLevel: их в текущей сессии меняют командами /model и /effort.
  • Проверка — /status покажет строку Setting sources со списком загруженных файлов.

Примеры

Личный ~/.claude/settings.json: модель, язык ответов, без подсказок под спиннером, история за 30 дней, git diff без вопросов.

Командный .claude/settings.json — коммитится в репозиторий, и у всех одинаковые правила, переменные и хук, который проверяет каждую команду перед запуском.

Личное — в settings.local.json. Если команда задала в проекте одно, а вам нужно другое, не правьте общий файл: тот же ключ в .claude/settings.local.json перекроет его только для вас.

Частые ключи

КлючЧто задаёт
modelМодель для новых сессий: "sonnet", "opus" или полный ID — см. Модели и выбор
effortLevelСколько модель думает по умолчанию: low, medium, high, xhigh
permissionsПравила allow / ask / deny, стартовый режим defaultMode, доп. папки — см. Разрешения и режимы
envПеременные окружения для сессии и всех запускаемых команд
hooksСвои команды на событиях: до и после инструмента, в конце ответа — см. Хуки
languageЯзык ответов Claude
outputStyleСтиль ответов, например "Explanatory" — с пояснениями по ходу работы
statusLineСвоя строка состояния под полем ввода
enabledPluginsКакие плагины включены
autoMemoryEnabledВключить или выключить автопамять
attributionПодпись Claude в коммитах и PR
sandboxПесочница: ограничивает командам доступ к файлам и сети (macOS, Linux, WSL2)
cleanupPeriodDaysСколько дней хранить историю сессий

Где не сработает. Чтобы чужой репозиторий не мог ослабить защиту, часть ключей из проектного файла игнорируется: например, defaultMode со значением auto или bypassPermissions. А allow-правила из него начинают действовать только после того, как вы доверитесь папке.
