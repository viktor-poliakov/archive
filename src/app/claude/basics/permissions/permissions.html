Разрешения и режимы

Claude Code сам читает файлы, но перед тем как что-то изменить — запустить команду, поправить файл, сходить в сеть — спрашивает разрешения. Режим задаёт, насколько часто он спрашивает, а правила allow / ask / deny — точечные исключения: «это делай молча», «это всегда спрашивай», «это никогда».

Что спрашивается по умолчанию

ДействиеСпрашивает«Да, больше не спрашивать»
Чтение файлов, поискНет, в пределах рабочей папки—
Команды в терминалеДа, кроме безопасных вроде ls или git statusНавсегда для этого репозитория и команды
Правка файловДаДо конца сессии
Загрузка страниц (WebFetch)Да, кроме популярных сайтов с документациейНавсегда для этого репозитория и домена

Ответ «да, больше не спрашивать» Claude Code записывает как allow-правило в .claude/settings.local.json в корне репозитория — это ваш личный файл, в git он не попадает.

Режимы

РежимБез вопросов выполняетКогда брать
default (Manual)Только чтениеХотите видеть каждое действие
acceptEditsЧтение, правки файлов, mkdir/mv/cp в рабочей папкеРаботаете над кодом и сами смотрите дифф
planТолько чтение и исследование, файлы не правитСначала продумать, потом менять — см. Plan mode
autoВсё, но команды и запросы в сеть сначала проверяет отдельная модель-классификаторДлинные задачи, когда вопросы мешают
dontAskТолько заранее разрешённое правилами, остальное отклоняетCI и скрипты
bypassPermissionsВсё, без проверокТолько изолированный контейнер или VM
  • В сессии — Shift+Tab переключает по кругу default → acceptEdits → plan, а если доступен, то и auto. Текущий режим виден под полем ввода.
  • В десктопе и VS Code — переключатель режима рядом с полем ввода.
  • При запуске — флаг --permission-mode:

Режим, с которого начинается каждая сессия, задаётся в settings.json. Свежие версии в терминале и VS Code и так стартуют в auto, если он доступен для вашей модели, а claude -p — в default.

Осторожно с bypassPermissions (он же флаг --dangerously-skip-permissions). Claude сможет удалить файлы, переписать .git или выполнить команду из вредоносной страницы — защиты от prompt injection нет. Значения auto и bypassPermissions в проектном .claude/settings.json игнорируются: чужой репозиторий не может включить их за вас.

Правила allow, ask, deny

Правила лежат в permissions любого файла настроек, а команда /permissions показывает их все с указанием, из какого файла каждое. Пример для проекта: npm-скрипты и коммиты — молча, пуш — с вопросом, секреты — никогда:

ПравилоЧто означает
BashЛюбая команда
Bash(npm run build)Ровно эта команда
Bash(npm run *)npm run с любыми аргументами
Read(./.env)Чтение .env в текущей папке
Edit(/src/**/*.ts)Правка .ts в src от корня проекта
Read(~/.ssh/**)Чтение из домашней папки; //path — абсолютный путь
WebFetch(domain:example.com)Загрузка страниц с домена
mcp__github__*Все инструменты MCP-сервера github
  • Порядок — сначала deny, потом ask, потом allow; срабатывает первое совпадение. Узкое allow не пробьёт широкое deny: Bash(aws *) в deny заблокирует и aws s3 ls, даже если оно разрешено.
  • Звёздочка после подкоманды — Bash(git log *) разрешает только git log, а Bash(git *) — вообще любые команды git, включая push.
  • Цепочки команд — каждая часть проверяется отдельно: Bash(npm test *) не разрешит npm test && rm -rf dist.
  • Правило сравнивается с текстом — deny на Bash(git push *) не поймает git -C . push, а deny на Read не помешает Python-скрипту открыть файл. Для жёсткой защиты нужна песочница (ключ sandbox) или хук.
  • Доверие к папке — allow-правила из закоммиченного .claude/settings.json заработают, только когда вы подтвердите доверие к папке в диалоге при первом запуске. Deny и ask действуют сразу.

Правила исполняет Claude Code, а не модель. «Никогда не трогай .env» в CLAUDE.md — просьба, которую Claude обычно выполняет. Read(./.env) в deny — запрет, который Claude Code проверяет сам, что бы ни решила модель.
