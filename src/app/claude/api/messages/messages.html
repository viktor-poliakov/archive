Messages API

Messages API — один эндпоинт POST /v1/messages, через который ваш код разговаривает с Claude. Отправляете историю диалога и получаете следующий ответ. Через него же идут картинки, PDF, инструменты, стриминг и JSON по схеме. Общие понятия — токены, роли, лимиты, цена — разобраны в LLM API. Здесь — как это устроено у Claude.

Установка и ключ

  • Ключ создают в Claude Console. Оплата — по токенам, отдельно от подписки Pro или Max: см. Тарифы и лимиты.
  • Ключ только на сервере. В браузерный или мобильный код его не кладут — запросы идут через ваш бэкенд.
  • SDK есть для TypeScript, Python, Java, Go, C#, Ruby и PHP. Через Bedrock, Vertex AI и Foundry — те же вызовы, только клиент свой, например @anthropic-ai/bedrock-sdk.

Параметры запроса

ПараметрЧто задаёт
modelclaude-opus-5-5, claude-sonnet-5-5, claude-haiku-5-5, claude-fable-5-1 — см. Модели и выбор
max_tokensОбязателен. Потолок длины ответа: модель упёрлась в него — ответ обрывается
messagesИстория диалога: реплики user и assistant, первой идёт user
systemСистемный промпт: роль, правила, постоянный контекст
output_configeffort — сколько модель думает и тратит токенов, от low до max. По умолчанию high, у Opus 5.5 и Haiku 5.5 — medium. format — ответ строго по JSON-схеме
thinkingУ актуальных моделей рассуждения включены по умолчанию. { type: "adaptive", display: "summarized" } — получать их краткий пересказ
stop_sequencesСтроки, на которых генерация остановится
tools, tool_choiceИнструменты — см. Tool use
cache_controlКэш повторяющегося начала запроса — см. Prompt caching

Нет temperature, top_p и top_k. С версии API 2026-10-21 запрос с ними получает ошибку 400. Её отправляют SDK начиная с TypeScript 1.0 и Python 2.0. Ответ настраивают промптом, effort и схемой.

Что приходит в ответ

  • content — массив блоков, а не строка. Блок thinking может прийти, даже если вы не просили рассуждения, — с пустым текстом. Поэтому текст берут по type === "text", а не из content[0].
  • usage — сколько токенов ушло на вход и выход. По этим числам считается счёт.
stop_reasonЧто значит
end_turnОтвет закончен
max_tokensУпёрся в max_tokens: ответ обрезан
stop_sequenceВстретилась строка из stop_sequences
tool_useClaude просит вызвать инструмент — см. Tool use
pause_turnСерверный инструмент, например веб-поиск, взял паузу. Отправьте ответ обратно, и Claude продолжит
refusalОтказ по соображениям безопасности, категория — в stop_details. Параметр fallbacks (бета) повторит запрос на другой модели автоматически

Диалог

API не хранит переписку: каждый запрос несёт всю историю. Ответ Claude добавляйте в messages целиком, как массив content, а не только его текст. Иначе потеряются вызовы инструментов и рассуждения.

Стриминг

Текст приходит по мере генерации — для чатов и длинных ответов. Большой max_tokens без стриминга может упереться в таймаут HTTP.

Картинки и PDF

Вместо строки в content передают массив блоков: image, document и text. Файл можно дать ссылкой или в base64:

  • PDF — до 600 страниц и 32 МБ на запрос. Claude видит и текст, и картинки страниц.
  • Один файл во многих запросах — загрузите его в Files API (client.files.upload) и ссылайтесь по file_id.

JSON по схеме

Structured outputs: ответ гарантированно совпадает со схемой, ни парсить текст, ни просить «верни только JSON» не нужно. Удобнее всего — схема на Zod и messages.parse():

В Python так же, только схема — модель Pydantic. Без хелперов схему передают в output_config.format как JSON Schema.

Что ещё есть рядом

  • Message Batches — пачка запросов асинхронно и вдвое дешевле, когда ответ не нужен сразу.
  • Подсчёт токенов — client.messages.countTokens(...) посчитает вход до отправки.
  • Models API — client.models.list(): какие модели доступны, их контекст и возможности.
  • Ошибки — SDK сам повторяет запрос при 429 и 5xx (по умолчанию дважды). Остальное ловите по классам: Anthropic.RateLimitError, Anthropic.BadRequestError…
