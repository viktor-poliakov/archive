Managed Agents

Managed Agents — агент, который целиком работает у Anthropic. Цикл «Claude думает → вызывает инструмент» идёт на их серверах. Инструменты — Bash, файлы, поиск по коду, веб — выполняются в изолированном контейнере, отдельном для каждой сессии. Вы один раз описываете агента, потом запускаете сессии с задачами и читаете поток событий. Свой сервер с песочницей и свой цикл не нужны. Сейчас это бета.

Агент и окружение

SDK тот же, что для Messages API (npm install @anthropic-ai/sdk), вызовы — в client.beta. Бета-заголовок SDK подставляет сам. Это установочный шаг: выполняется один раз, а не на каждый запрос.

  • Не создавайте агента на каждый запуск. Сохраните ID и меняйте агента через agents.update(): появится новая версия, а уже идущие сессии останутся на своей.
  • Как файлы в репозитории — агентов и окружения можно описать файлами и синхронизировать командой ant apply из CLI Anthropic.
  • Веб-инструменты выключайте, если задача их не требует. При сети limited они ходят только на хосты из allowed_hosts.

Запуск задачи

Сессия подключает к контейнеру репозиторий. Задачу отправляют событием, а результат читают из потока:

  • Поток — до отправки задачи. Он отдаёт только события после подключения.
  • session.status_idle — агент закончил и ждёт. Если stop_reason — requires_action, ждёт именно вас: подтверждения вызова или результата вашего инструмента.
  • Сообщения можно слать, пока агент работает: они встанут в очередь.
  • Ход работы видно в Console: platform.claude.com/workspaces/default/sessions/<id> покажет переписку, каждый вызов инструмента и стоимость.
  • Файлы результата агент кладёт в /mnt/session/outputs/. Список — client.beta.files.list({ scope_id: session.id, betas: ["managed-agents-2026-04-01"] }): здесь бета-заголовок нужно передать явно.

Инструменты и разрешения

permission_policyЧто делает
always_allowВызов выполняется сразу. Вариант по умолчанию для встроенных инструментов
always_askКаждый вызов ждёт user.tool_confirmation. Вариант по умолчанию для MCP
autoСервер сам оценивает вызов: выполняет, запрещает или спрашивает вас (evaluated_permission: "ask"). Если отвечать некому — отвечайте deny
  • Свои инструменты — { type: "custom", name, description, input_schema } в tools. Агент присылает agent.custom_tool_use, ваш код выполняет его и отвечает user.custom_tool_result.
  • MCP-серверы объявляют в агенте (mcp_servers), а токены к ним хранят в vault и подключают к сессии. Так же в vault хранят ключи для CLI и API: в контейнер они не попадают, сервер подставляет их на выходе.

Что ещё умеет

  • Outcomes — вместо сообщения задаёте результат и критерии (user.define_outcome). Отдельный проверяющий оценивает работу, и агент дорабатывает её, пока критерии не выполнены (по умолчанию до 3 попыток).
  • Расписание — deployments.create() с cron-выражением: агент запускается сам, например каждую ночь.
  • Память — memory stores: агент помнит выводы между сессиями.
  • Несколько агентов в одной сессии — координатор раздаёт подзадачи помощникам.
  • Бюджет — budget при создании сессии: жёсткий потолок в долларах. Дойдя до него, сессия встаёт на паузу.

Сколько стоит

  • Веб-поиск — $10 за 1000 запросов.
