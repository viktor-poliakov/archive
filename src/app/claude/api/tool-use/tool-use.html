Tool use

Tool use — способ дать Claude ваши функции: поиск заказа, запрос к БД, отправку письма. Сам Claude ничего не выполняет. Он отвечает блоком tool_use — «вызови get_order_status с orderId: "1042"», — а ваш код выполняет вызов и возвращает результат. Это обычный Messages API, только с полем tools. Сама идея и типичные ошибки разобраны в разделе Агенты, tool use, MCP.

Как проходит вызов

  1. Запрос с tools — вы передаёте описания инструментов вместе с сообщениями.
  2. Ответ с stop_reason: "tool_use" — в content есть блоки tool_use: id, имя инструмента и аргументы в input.
  3. Вы выполняете функцию и отправляете следующий запрос: история плюс сообщение user с блоками tool_result, у каждого tool_use_id своего вызова.
  4. Повторяете, пока stop_reason не станет end_turn. Тогда в ответе — итоговый текст.

Описание инструмента

  • description — главное поле. По нему Claude решает, звать ли инструмент. Пишите не только что он делает, но и когда его вызывать.
  • input_schema — JSON Schema аргументов. Описание у каждого поля, enum для фиксированного набора значений.
  • strict: true — аргументы гарантированно пройдут схему: без лишних полей и неверных типов. Схеме нужны additionalProperties: false и required.
  • Описания — это входные токены каждого запроса. Держите набор коротким: десятки похожих инструментов дороже и путают модель.

Цикл вручную

Полный цикл с инструментом из примера выше: Claude спрашивает статус заказа, получает его и отвечает пользователю.

  • Ответ Claude — в историю целиком, вместе с блоками tool_use. Без них API не поймёт, к чему относятся tool_result.
  • Все результаты — одним сообщением. Claude может попросить несколько вызовов сразу. Если раскидать ответы по разным сообщениям, он начнёт реже вызывать инструменты параллельно.
  • Ошибку — в tool_result с is_error: true и понятным текстом. Не выкидывайте вызов: на каждый tool_use нужен ответ.
  • Опасные действия — оплату, письма, удаление — подтверждает человек перед выполнением. А то, что вернул инструмент, — данные, а не команды: см. промпт-инъекции.

Tool runner: цикл делает SDK

Тот же агент без ручного цикла. Инструмент — схема на Zod и функция run, остальное SDK делает сам:

  • Исключение из run раннер сам превращает в tool_result с is_error: true.
  • Без Zod — betaTool() из @anthropic-ai/sdk/helpers/beta/json-schema принимает обычную JSON Schema.
  • Python — декоратор @beta_tool над обычной функцией: схема берётся из сигнатуры и docstring. Запуск — client.beta.messages.tool_runner(...).
  • Бета — поэтому client.beta. Перехватить вызов, например для подтверждения, можно и здесь: проверьте его внутри run.

Готовые инструменты Anthropic

Серверные инструменты выполняются у Anthropic: их достаточно объявить, цикл писать не нужно.

ИнструментtypeКто выполняет
Веб-поискweb_search_20260209Anthropic
Чтение страницы по ссылкеweb_fetch_20260209Anthropic
Код в песочнице: Python, Bash, файлыcode_execution_20260521Anthropic
Bashbash_20250124Вы
Редактор файловtext_editor_20250728Вы
Память между сессиямиmemory_20250818Вы, хранилище ваше
  • Клиентские (Bash, редактор, память) объявляют без input_schema: формат вызова Claude уже знает. Выполняет их ваш код, как обычные инструменты.
  • pause_turn — серверный цикл взял паузу. Отправьте ответ обратно как есть, без «продолжай», и Claude доделает. Tool runner такие паузы сам не продолжает.
  • web_fetch открывает только ссылки, которые уже есть в разговоре: от пользователя или из результатов поиска.
  • Удалённый MCP-сервер можно подключить прямо в запросе (MCP connector, бета). Тогда Claude вызывает его инструменты сам, без вашего цикла.
