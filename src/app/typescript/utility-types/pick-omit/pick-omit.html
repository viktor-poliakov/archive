TypeScript/Утилитарные типы/Pick, Omit

Pick, Omit

Pick и Omit — это как заказ в кафе по меню. Есть большое меню (готовый тип со всеми полями), а вам нужна лишь часть. Pick — вы ставите галочки только напротив тех блюд, что берёте, а всё остальное меню как будто исчезает. Omit — наоборот: вы говорите «несите всё, кроме одного-двух пунктов» (например, «всё, кроме пароля»). Оба не создают новое меню с нуля — они вырезают нужный кусок из уже существующего типа, а значит, ничего не приходится дублировать вручную.

Боль без Pick и Omit: копипаста полей

Представьте большой тип — «полную анкету» пользователя. В ней много полей: id, имя, почта, пароль, дата регистрации. В разных местах приложения вам нужна не вся анкета целиком, а её кусочки: где-то только имя и id (для маленькой карточки в списке), где-то всё, кроме пароля (чтобы безопасно отдать данные на сайт). Что делает новичок? Копирует нужные поля руками в новый тип.

Вроде работает. Но это копипаста: описание полей продублировано. Стоит поменять что-то в исходном User — скажем, сделать id строкой вместо числа — и придётся вручную вспомнить про все ручные копии и починить каждую. Про одну обязательно забудешь, и типы «разъедутся»: в одном месте id — число, в другом — строка. Хочется способ, при котором маленький тип сам следует за большим. Ровно это и дают Pick и Omit.

Что такое «ключ» (поле). У объектного типа { id: number; name: string } ключи — это имена свойств: id и name. Именно с ключами работают Pick и Omit: они решают, какие поля оставить, а какие выбросить. Подробнее про извлечение имён полей — на странице keyof.

Pick<T, K>: оставить только выбранное

Pick<T, K> строит новый тип, оставляя из типа T только те ключи, что перечислены в K. Здесь T — исходный тип (наше «меню»), а K — имена полей, которые вы «отмечаете галочкой». Если полей несколько, их соединяют вертикальной чертой | — это запись объединения имён: 'id' | 'name' читается как «id или name».

Заметьте главное отличие от ручной копии из первого раздела: мы нигде не переписали id: number заново. Мы сослались на поля User по имени. Поэтому UserPreview — не отдельная независимая копия, а «живой срез»: поменяется User — автоматически поменяется и превью. Один источник правды.

Omit<T, K>: оставить всё, кроме

Omit<T, K> — полная противоположность Pick. Он берёт тип T целиком и выбрасывает из него ключи K. Всё остальное остаётся на месте. Это самый удобный инструмент, когда «лишних» полей мало, а оставить нужно почти всё. Классика жанра — убрать пароль перед отправкой данных на клиент:

Omit — это дополнение Pick

Между Pick и Omit есть красивая связь: они описывают одно и то же с двух сторон. Всё, что можно выразить через «оставить вот эти», можно выразить и через «выбросить все остальные», — и наоборот. Результат получится буквально одинаковым.

Отсюда простое правило выбора: смотрите, чего меньше писать. Нужно оставить всего пару полей из двадцати — берите Pick. Нужно убрать одно-два поля, а остальное сохранить — берите Omit. Оба одинаково корректны; выбирают тот, что короче и понятнее читается.

Частая путаница: Pick/Omit — это НЕ Exclude/Extract

Это ловушка, в которую попадают почти все новички, поэтому остановимся на ней отдельно. Есть похожая по звучанию пара — Exclude и Extract, — и её постоянно путают с Pick/Omit. Разница принципиальная и запоминается легко, если один раз её понять.

Pick и Omit работают с ключами объектного типа — то есть с полями структуры вроде { id; name; email }. А Exclude и Extract работают с членами объединения — вариантами из набора допустимых значений вроде 'admin' | 'editor' | 'guest'. Это два совершенно разных «материала»:

Вопрос Pick / Omit Exclude / Extract
С чем работают ✅ поля объекта { ... } ❌ не поля — варианты union
Что режут ✅ ключи (имена свойств) ❌ члены объединения A | B
Пример входа User с полями 'admin' | 'editor'
Результат объект с меньшим числом полей объединение с меньшим числом вариантов

Запомнить просто: видите объект с полями — режете поля через Pick/Omit; видите цепочку значений через | — режете варианты через Exclude/Extract. Подробный разбор второй пары — на странице Exclude, Extract.

Коротко

  • Pick<T, K> строит новый тип, оставляя из T только ключи K. Это «галочки в меню»: беру вот эти поля, остальное убираю.
  • Omit<T, K> оставляет из T всё, кроме ключей K. Это «всё, кроме пароля»: выбрасываю пару полей, остальное сохраняю.
  • K — это имена ключей, соединённые вертикальной чертой |: 'id' | 'name'. Разрешены только реальные ключи типа — опечатка сразу даёт ошибку компиляции.
  • Omit — дополнение Pick: любой срез выразим и «оставить вот эти», и «выбросить остальные». Выбирайте тот вариант, где меньше писать.
  • Не копипаста. Срез ссылается на исходный тип: меняется большой тип — срез обновляется сам. Один источник правды.
  • Не путать с Exclude/Extract. Pick/Omit режут поля объекта; Exclude/Extract режут варианты объединения.
