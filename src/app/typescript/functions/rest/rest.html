Rest-параметры

Обычно у функции фиксированный список параметров. Но иногда заранее неизвестно, сколько аргументов передадут: сложить два числа или двадцать, вывести одну метку или десяток. Для этого есть rest-параметр — три точки перед именем, которые собирают все оставшиеся аргументы в один массив: function sum(...nums: number[]). Разберём синтаксис, строгие правила расстановки и одну частую путаницу — где «три точки» собирают, а где, наоборот, разворачивают.

Аналогия. Rest-параметр — как один большой почтовый мешок в конце сортировки. Первые письма могут раскладывать по именным ячейкам (обычные параметры), но все оставшиеся письма, сколько бы их ни пришло, падают в один мешок. Мешок всегда один, и стоит он в самом конце — иначе непонятно, где заканчивается «всё остальное».

Синтаксис: три точки

Rest-параметр пишется так же, как в JavaScript (rest-параметры в JS): три точки ..., затем имя. Новое в TypeScript — тип. И тут главное правило: тип rest-параметра — это всегда тип массива (number[], string[] и т. п.), потому что внутри функции rest и есть массив собранных аргументов. При этом каждый переданный аргумент должен подойти под тип элемента этого массива.

Обратите внимание: вызвать функцию можно с любым числом аргументов — тремя, двумя или вовсе без них (тогда массив окажется пустым). А вот сорт данных строго проверяется: подсунуть строку туда, где ждут number[], не выйдет.

Почему так. Тип элемента и тип rest-параметра связаны просто: если каждый аргумент — string, то собранные вместе они дают string[]. Поэтому написать ...x: number нельзя — компилятор сразу отвечает A rest parameter must be of an array type.: rest без массива не бывает.

Правила: один rest и только последним

У rest-параметра два жёстких ограничения, и оба следуют из его смысла «забрать всё остальное»:

  • rest-параметр в функции может быть только один;
  • он обязан стоять последним в списке параметров.

Обычные (именованные) параметры при этом спокойно стоят перед rest: сначала TypeScript раздаёт аргументы им по порядку, а всё, что осталось, отправляет в rest-массив.

А вот поставить обычный параметр после rest или завести второй rest нельзя — тогда стало бы неясно, где заканчивается «всё остальное» и начинается следующий параметр:

Важно. Отсюда же вытекает совместимость с необязательными и дефолтными параметрами (о них — на странице Параметры функций): rest как бы «продолжает» необязательные, ведь ноль собранных аргументов — это нормально. Но и необязательный параметр после rest поставить всё равно нельзя: последнее место занято.

rest при объявлении и spread при вызове

Одни и те же три точки означают противоположные вещи в зависимости от того, где стоят. В списке параметров (при объявлении функции) они собирают аргументы в массив — это rest. В месте вызова они, наоборот, разворачивают готовый массив обратно в отдельные аргументы — это spread. Собрать и разложить — зеркальные операции.

При развороте массива в rest-вызов TypeScript тоже проверяет типы: элементы массива должны подходить под тип элемента rest-параметра. Развернуть string[] в функцию, которая ждёт number[], не получится.

Кортежные rest (продвинутое)

Обычно тип rest — это «однородный» массив: сколько угодно элементов одного типа. Но rest можно типизировать и кортежем (массивы и кортежи) — тогда из «сколько угодно» он превращается в фиксированный набор аргументов на конкретных позициях, каждый со своим типом.

По сути function makePair(...args: [number, string]) — это тот же function makePair(a: number, b: string), только аргументы попадают в массив args. Компилятор следит и за количеством (Expected 2 arguments), и за порядком типов.

Подписанные элементы кортежа

Элементам кортежа можно дать имена-подписи — они ни на что не влияют во время выполнения, но делают подсказки редактора понятнее. И тут открывается приём: в подписанном кортеже можно смешать фиксированные позиции и хвост из «сколько угодно» — например, [id: number, ...labels: string[]] означает «сначала обязательное число, затем любое количество строк».

Зачем это на практике: обёртка с теми же аргументами

Частая задача — написать обёртку над функцией: добавить что-то вокруг вызова (запись в лог, замер времени, проверку прав), но аргументы принять и передать дальше ровно те же, что у исходной функции. Если выписывать список параметров руками, то при любом изменении исходной функции обёртка молча «рассинхронится» — и ошибку никто не подсветит.

Здесь и выручает встроенная утилита Parameters<F>: она берёт функцию и возвращает её параметры как кортеж. Этот кортеж мы кладём в rest обёртки — (...args: Parameters<typeof fn>) — а при вызове разворачиваем обратно — fn(...args). Те самые «три точки»: слева собирают аргументы, справа разворачивают.

Если совсем коротко: ...args: Parameters<typeof fn> значит «принимай те же аргументы, что и fn», а fn(...args) — «передай их дальше без изменений». Сама утилита Parameters<> и её родственники разобраны на странице ReturnType, Parameters — отдельно знать их для этой темы не обязательно.

Кратко

  • Rest-параметр — три точки перед именем; он собирает все оставшиеся аргументы вызова в один массив: function sum(...nums: number[]).
  • Тип rest — всегда тип массива; каждый переданный аргумент должен подойти под тип элемента.
  • rest может быть только один и стоять последним; обычные параметры могут идти перед ним.
  • Три точки в списке параметров собирают (rest), а в месте вызова — разворачивают массив в аргументы (spread).
  • При развороте массива в rest-вызов элементы должны совпадать по типу с элементом rest-параметра.
  • rest можно типизировать кортежем для фиксированного набора позиций: ...args: [number, string]; элементы кортежа можно подписать и смешать с хвостом [id: number, ...labels: string[]].
