Типы возврата

У функции есть не только параметры «на входе», но и результат «на выходе» — то, что она отдаёт вызвавшему её коду. Тип возврата описывает этот результат: число, строку, объект, а иногда — особые случаи «ничего полезного» (void) или «вообще не возвращает» (never). В этом уроке разберём, где записывается тип возврата, зачем указывать его явно, и пройдёмся по специальным типам: void, never и Promise.

Явный тип возврата и вывод

Тип возврата пишут после круглых скобок с параметрами, через двоеточие — и уже перед телом функции. В сигнатуре function toNumber(s: string): number кусочек : number и есть обещание: «эта функция отдаст наружу число».

TypeScript умеет вывести тип возврата сам — из того, что стоит в return. Так что аннотацию можно и не писать. Тогда зачем указывать её явно? По двум причинам: она документирует намерение (читателю сразу ясно, что вернёт функция) и заставляет компилятор сверить тело с обещанием, ловя ошибку в самом источнике, а не там, где результат используют.

Аналогия. Явный тип возврата — как надпись на выходном лотке автомата: «здесь выдаётся кофе». Без надписи вы поймёте, что там, только заглянув внутрь (это и делает вывод типов). С надписью же контролёр сразу поймает брак: если автомат по ошибке начал сыпать в кофейный лоток чай — несоответствие заметят прямо у автомата, а не у разочарованного покупателя.

Как явный тип ловит ошибку внутри тела

Разница видна на примере с ошибкой. Без аннотации неверный тип «протекает» наружу и всплывает в чужом месте — там, где результат пытаются использовать. С явным : number компилятор ругается прямо на return, у причины.

Для опытных. Явный тип возврата ещё и стабилизирует публичный контракт функции: пока подпись не меняется, случайная правка тела не «утечёт» в выведенный тип и не сломает вызывающий код незаметно. Для экспортируемых функций это особенно ценно. Подробнее про сам механизм — на странице Вывод типов.

void — функция ничего не возвращает

Некоторые функции нужны ради действия, а не результата: записать в лог, показать сообщение, сохранить данные. Они не отдают полезного значения — их тип возврата void. Внутри такой функции либо вовсе нет return, либо стоит пустой return; без значения (обычно для раннего выхода).

Значение типа void бесполезно как данные: фактически это undefined, и использовать его в вычислениях нельзя. Тип void словно говорит: «результата тут не жди, смотри на побочный эффект».

Тонкость: колбэк с void может вернуть значение

Есть неочевидный, но важный нюанс. Если функция ожидает колбэк с типом возврата void, то переданный колбэк вправе вернуть какое-нибудь значение — оно просто будет проигнорировано. Классический пример: forEach ждёт колбэк, возвращающий void, а метод push возвращает number (новую длину массива) — и всё равно так писать можно.

Почему так. Это называют контекстным типом возврата void. Тип void в позиции колбэка означает не «обязан вернуть undefined», а «мне не важно, что ты вернёшь, — я всё равно это не использую». Так удобнее писать короткие стрелки вроде (n) => list.push(n), не оборачивая тело в фигурные скобки только ради того, чтобы «проглотить» результат. Обратная сторона: сам вызывающий код (тот же forEach) на этот результат опираться не должен.

never — функция никогда не возвращает

Тип never означает, что функция вообще не возвращает управление вызвавшему коду. Так бывает в двух случаях: функция всегда бросает исключение либо уходит в бесконечный цикл. Важно не путать его с void: void-функция возвращается, просто без значения; never-функция не возвращается вовсе — код после её вызова недостижим.

void never
Возвращает управление? ✅ да, возвращается ❌ нет, не возвращается
Есть полезное значение? нет (по сути undefined) значения не бывает в принципе
Типичный случай лог, сохранение, обработчик события бросок ошибки, вечный цикл
Код после вызова выполнится дальше недостижим

Дальше. Оба этих типа с их тонкостями (например, зачем never нужен для проверки полноты switch) подробно разобраны на отдельной странице void и never.

Асинхронные функции — Promise

Функция, помеченная async, всегда возвращает Promise — даже если внутри вы пишете return 42. Компилятор автоматически оборачивает результат: число превращается в Promise<number>. Поэтому тип возврата async-функции почти всегда записывают как Promise<ЧтоВнутри>, например async function load(): Promise<number>.

Обещанный внутренний тип компилятор проверяет: вернёте из Promise<number>-функции строку — получите ошибку прямо на return. А чтобы достать значение из Promise, его разворачивают через await: await load() даёт уже number, а не Promise<number>. Если асинхронная функция не отдаёт полезного результата, её тип — Promise<void>.

Важно. Указывать тип возврата number у async-функции нельзя — компилятор потребует именно Promise<number>. Ошибка новичка «функция ведь возвращает число» здесь не работает: значение станет доступным как число только после await, а сама функция всегда отдаёт обёртку-обещание.

Возврат объединения или объекта

Результат не обязан быть одним простым типом. Функция может вернуть объединение, например number | null или User | null, — и тогда вызывающий код обязан разобрать каждый случай. Может вернуть и целый объект, упаковав несколько значений вместе.

Пока результат может быть null, компилятор не даст обратиться к полю напрямую — сначала нужно проверкой сузить тип. Как это работает, подробно на странице Объединения и сужение.

Особые типы возврата: проверки во время выполнения

Наконец, есть два необычных вида типа возврата, которые описывают не «какое значение вернём», а проверку, влияющую на типы. Это предикаты типа (x is Foo) и сигнатуры-утверждения (asserts x is Foo). Оба говорят компилятору, как сузить тип аргумента после вызова функции.

Это большая отдельная тема — здесь достаточно знать, что такие «типы возврата» существуют. Подробно про них — на страницах Пользовательские защитники типов и Функции-утверждения.

Кратко

  • Тип возврата пишут после скобок с параметрами: function toNumber(s: string): number. TypeScript умеет вывести его сам.
  • Указывать тип явно полезно: он документирует намерение и заставляет компилятор проверить тело, ловя ошибку в источнике, а не в месте вызова.
  • void — функция не отдаёт полезного значения (лог, сохранение). Колбэк с void вправе вернуть значение — оно игнорируется (контекстный void).
  • never — функция никогда не возвращается: всегда throw или вечный цикл. Отличается от void, который возвращается, просто без значения.
  • async-функция всегда возвращает Promise: тип пишут как Promise<number>, значение достают через await.
  • Функция может вернуть объединение (User | null) или объект; при null вызывающий код обязан сузить тип проверкой.
  • Особые типы возврата x is Foo и asserts x is Foo описывают проверки времени выполнения — см. защитники типов и функции-утверждения.
