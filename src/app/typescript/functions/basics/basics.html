Типизация функций

В JavaScript функция принимает что угодно: передадите строку вместо числа — язык не возразит, а ошибка вылезет уже во время работы программы. TypeScript позволяет описать функцию точнее: сказать, что в неё входит (типы параметров) и что из неё выходит (тип результата). Дальше компилятор сам следит, чтобы этот «договор» соблюдался — и ловит несоответствия ещё до запуска. Если устройство JS-функций пока в новинку — загляните в раздел Основы функций, а здесь мы добавляем к ним типы.

Аналогия. Функция — как рецепт на кухне. Рецепт заранее оговаривает, какие ингредиенты определённого сорта нужно положить (два числа, а не «щепотку строки») и какое блюдо получится на выходе (число). Аннотации типов — это и есть такие пометки в рецепте: они не готовят за вас, но не дают перепутать соль с сахаром.

Аннотации параметров и результата

Тип параметра пишут через двоеточие сразу после его имени: a: number. Тип результата ставят после круглых скобок, тоже через двоеточие: function add(a: number, b: number): number. Читается как «функция add берёт два числа и возвращает число».

Главная выгода — ошибку с неверным аргументом видно до запуска, прямо в редакторе. В чистом JavaScript такой промах тихо дожил бы до продакшена.

Стрелочные функции

У стрелочных функций всё устроено так же: типы параметров — в скобках, тип результата — после скобок, перед стрелкой =>. Например, const square = (x: number): number => x * x.

Важно. Не путайте стрелку значения (=> в самой функции — она реально что-то вычисляет) со стрелкой типа, о которой пойдёт речь ниже. Выглядят одинаково, но одна создаёт функцию, а вторая лишь описывает её форму.

Вывод типа возврата

Тип результата можно не писать вовсе — TypeScript прочитает тело функции и выведет его сам. Если double возвращает x * 2, а x — число, то и результат — число; компилятор поймёт это без подсказки. Подробнее про то, как работает автоматический вывод типов.

Когда всё-таки писать тип явно

Раз TypeScript и так всё выводит, зачем указывать тип результата руками? Есть два веских повода:

  • Публичный API. Явный тип фиксирует «договор» функции. Если тело случайно начнёт возвращать не то, ошибка загорится у самого объявления, а не разлетится по всем местам, откуда функцию вызывают.
  • Ранняя ловля ошибок в теле. С явным : number опечатка внутри функции подсвечивается прямо там, где написана, — а не «уезжает» к вызывающему коду в виде загадочного несоответствия типов.

Для опытных. Разумный компромисс: для внутренних мелких функций полагаться на вывод, а на границах модулей и в экспортируемых функциях писать тип результата явно. Тонкости и приёмы собраны на странице Типы возвращаемого значения.

Тип функции как значение

В TypeScript функция — такое же значение, как число или строка, а значит у неё есть свой тип. Записывается он стрелкой: (a: number, b: number) => number — «берёт два числа, возвращает число». Чтобы на такой тип было удобно ссылаться, ему обычно дают имя через type: например type MyCb = (a: number) => number — «функция, которая берёт одно число и возвращает число». Такой function type expression ставят там же, где любой другой тип: на переменную, на параметр-колбэк, на поле объекта.

Переменной с типом-функцией можно присвоить любую функцию подходящей формы; несовпадение компилятор отвергнет. Обратите внимание: у присваиваемой функции параметры уже не нужно аннотировать — их типы TypeScript возьмёт из объявленного типа переменной (это называют контекстной типизацией).

Типизация колбэка

Самое частое применение — описать колбэк, функцию-аргумент. Тип параметра-колбэка задаётся тем же выражением со стрелкой, и тогда компилятор проверит, что переданная функция и принимает, и возвращает то, что нужно.

Параметр без типа — неявный any

Если у параметра не написать тип, TypeScript нечего проверять — и он молча присвоил бы такому параметру тип any, который отключает все проверки. Чтобы это не проходило незаметно, строгий режим (флаг noImplicitAny, он входит в strict) считает неявный any ошибкой.

Лечится всегда одинаково — дописать аннотацию. После этого параметр снова под контролем компилятора, и неверный вызов подсветится. Осознанный any (написанный руками) допустим, но это последнее средство: он выключает проверки там, где стоит.

Функция без результата: void

Иногда функция ничего не возвращает — только делает что-то «в сторону»: печатает в консоль, пишет в лог. Тип её результата — void. Чаще его тоже выводят автоматически, но можно указать и явно.

Дальше. У void есть тонкости (например, чем он отличается от undefined и от «никогда не возвращающего» never) — про них читайте на страницах Типы возвращаемого значения и void и never.

Кратко

  • Тип параметра пишут после его имени через двоеточие, тип результата — после круглых скобок: function add(a: number, b: number): number.
  • Неверный аргумент ловится до запуска, прямо в редакторе, а не в продакшене.
  • У стрелочных функций аннотации ставят так же: const square = (x: number): number => x * x.
  • Тип результата можно не писать — TypeScript его выведет; но для публичного API и ранней ловли ошибок его указывают явно.
  • У функции есть свой тип-стрелка: (a: number, b: number) => number. Это описание формы (для переменных и колбэков), а не сама функция.
  • Параметр без аннотации получает неявный any — при noImplicitAny это ошибка; лечится добавлением типа.
  • Функция, которая ничего не возвращает, имеет результат void.
