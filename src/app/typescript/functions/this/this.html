Типизация this

Из JavaScript вы уже знаете капризную черту this: в обычной функции его значение зависит не от того, где функция описана, а от того, как её вызвали (напоминание — Контекст: основы и this в функциях). TypeScript это поведение не меняет, но добавляет то, чего в JavaScript нет: возможность заранее описать, каким должен быть this, и проверить это ещё до запуска программы. В этом уроке разберём this-параметр, потерю контекста, стрелочные функции и флаг noImplicitThis.

Проблема: this зависит от вызова

Начнём с знакомой ловушки. У объекта есть метод, который читает своё поле через this. Пока метод вызывают «через точку» (button.click()), всё работает. Но стоит оторвать метод от объекта и вызвать отдельно — и this перестаёт указывать на объект.

В чистом JavaScript такую ошибку вы увидите только во время выполнения — когда код уже упал. Логика та же, что описана на странице this в функциях: значение this «прикрепляется» в момент вызова. TypeScript же умеет предупредить об этом заранее — но лишь если вы расскажете ему, каким this ожидается. Как это сделать — дальше.

this-параметр

TypeScript разрешает объявить самый первый параметр с именем this — и в нём указать тип, который this обязан иметь внутри функции. Например, обработчик клика ожидает, что this — это кнопка:

Важно. this-параметр — это не настоящий аргумент. Вызывающий код его не передаёт: в примере выше addEventListener вызовет render с одним аргументом event, а сам this подставит браузер. Параметр this нужен исключительно как метка для компилятора и читателя: «внутри этой функции this должен быть вот таким».

Он стирается при компиляции

Раз this-параметр — только метка для проверки типов, в готовом JavaScript его нет вовсе. Компилятор просто вычёркивает его из сигнатуры, оставляя настоящие аргументы. Поэтому this всегда пишут первым и один раз — иначе TypeScript спутает его с обычным параметром.

Проверка метода, который опирается на this

this-параметр полезен не только для DOM-обработчиков. Опишите «одиночную» функцию, которую собираетесь присвоить объекту как метод, — и TypeScript проследит, что у this действительно есть нужные поля.

Здесь функция increment объявляет this: Counter, поэтому внутри неё разрешено обращаться к this.count. А присваивание { count: 0, increment } проходит проверку, потому что объект подходит под форму Counter.

Потеря контекста

Главная ценность this-параметра в том, что он превращает вчерашнюю рантайм-ошибку в ошибку компиляции. Ключевая идея: this стоит вне списка настоящих аргументов — это не значение, которое «едет внутри» функции, а требование к контексту вызова.

Именно поэтому «отрывание» метода опасно: значение, на которое рассчитывал this, при обычном вызове не подставится. С this-параметром TypeScript замечает это и подсвечивает ошибку прямо в редакторе.

Аналогия. this-параметр — как графа «кому адресовано» на бланке: она не часть содержимого письма, а условие доставки. Оторвали письмо от конверта (const detached = counter.increment) — адрес потерялся, и доставить его «просто так» уже нельзя. Подробнее о самом механизме потери контекста в JavaScript — на странице Потеря контекста.

Стрелочные функции и this

У стрелочной функции нет собственного this. Вместо того чтобы получать контекст в момент вызова, она берёт this из окружения — из того места, где стрелку описали (это называют лексическим this). Поэтому стрелка идеальна для колбэков внутри метода или класса: она сохраняет тот же this, что и снаружи.

Поскольку у стрелки нет своего this, ей и нечего описывать — объявить this-параметр у стрелочной функции нельзя, TypeScript на это ругается:

Про this обычная функция стрелочная функция
Откуда берётся this зависит от способа вызова из окружения (лексически)
Есть собственный this да нет
Можно объявить this-параметр ✅ да ❌ нет
Метод объекта, которому нужен this ✅ подходит ❌ не подходит — this не станет объектом
Колбэк внутри метода или класса ⚠ легко потерять this ✅ this сохраняется

Для опытных. Правило простое: для метода, которому нужен this объекта, берите обычную функцию (при необходимости добавьте this-параметр). Для колбэка, который должен помнить this окружающего кода, берите стрелку. Не пытайтесь навесить this-параметр на стрелку — у неё этого «слота» просто нет.

Флаг noImplicitThis

В строгом режиме (strict) автоматически включается флаг noImplicitThis. Он запрещает использовать this там, где компилятор не смог вывести его тип: вместо тихого any вы получаете явную ошибку. Это заставляет либо описать this-параметром, либо перейти на стрелку.

Обратите внимание: сообщение 'this' implicitly has type 'any' — это подсказка, а не придирка. Оно указывает ровно на те функции, где вы полагаетесь на this, но не сказали компилятору, каким он должен быть. Оба лекарства вы уже знаете: this-параметр или стрелочная функция.

Вспомогательные типы: ThisParameterType и OmitThisParameter

Когда функция объявляет this-параметр, встроенные утилиты позволяют работать с ним на уровне типов. ThisParameterType<T> достаёт тип this-параметра, а OmitThisParameter<T> возвращает тип той же функции, но без this — как будто контекст уже привязан (например, через .bind()).

Дальше. Эти утилиты нужны нечасто — в основном при работе с .bind() и обёртками над функциями. Как устроен сам синтаксис функций и их сигнатур — на странице Функции: основы.

Кратко

  • В обычной функции this зависит от способа вызова, а не от места описания — TypeScript это поведение не меняет.
  • this-параметр — фальшивый первый параметр function f(this: T, ...): он описывает требуемый this, но не является аргументом и стирается при компиляции.
  • С this-параметром компилятор ловит потерю контекста (const f = obj.method; f()) ещё до запуска.
  • У стрелочной функции нет своего this — она берёт его лексически из окружения; объявить this-параметр у стрелки нельзя.
  • Для метода — обычная функция (можно с this-параметром); для колбэка, помнящего внешний this, — стрелка.
  • Флаг noImplicitThis (входит в strict) требует, чтобы тип this был известен: чините this-параметром или стрелкой.
  • ThisParameterType<T> достаёт тип this-параметра, OmitThisParameter<T> убирает его из типа функции.
