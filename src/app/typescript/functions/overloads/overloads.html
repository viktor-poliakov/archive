Перегрузки функций

Иногда тип результата функции зависит от типов её аргументов: дали строку — вернётся строка, дали число — вернётся число. Одной сигнатурой такую связь точно не выразить: приходится писать string | number, и точность теряется. Перегрузки (function overloads) решают это — они позволяют показать вызывающему коду сразу несколько разрешённых форм вызова, у каждой со своим типом результата.

Проблема: одна сигнатура теряет точность

Возьмём функцию double: строку она склеивает саму с собой ('ab' → 'abab'), а число умножает на два (5 → 10). Логично ожидать: на строку — строку, на число — число. Но если описать вход и выход одним объединением string | number, компилятор потеряет связь между ними: он будет считать, что результат всегда string | number, даже когда мы точно знаем, что подали строку.

Формально ошибок в теле нет — беда в сигнатуре. Она честно говорит «может вернуться строка, а может число», и после вызова с известной строкой мы всё равно получаем размытый тип string | number. Вызвать строковый метод нельзя — вдруг там число. Нужна запись, которая свяжет конкретный вход с конкретным выходом.

Аналогия. Представьте автомат с надписью на кнопке «выдаёт монеты ИЛИ жетоны». Формально честно, но бесполезно: вы не знаете заранее, что получите, и приходится готовиться к обоим. Перегрузки — это как отдельные кнопки: «нажал монеты — точно монеты, нажал жетоны — точно жетоны».

Синтаксис перегрузок

Перегрузка состоит из двух частей. Сначала идут сигнатуры перегрузок — несколько объявлений без тела, только форма вызова с точкой с запятой на конце. Затем — одна реализация с телом, чьи параметры достаточно широки, чтобы покрыть все перечисленные перегрузки. Вот та же double, но точная:

Теперь double('ab') имеет тип string, а double(5) — number. Вызывающий код видит только две «витринные» сигнатуры и выбирает подходящую. Реализация double(x: string | number) — это внутренняя кухня: её задача только в том, чтобы обслужить обе перегрузки, и снаружи она не видна.

Важно. Реализацию пишут ровно одну, и её сигнатуру вызвать напрямую нельзя. Если написать только реализацию double(x: string | number) без строк-перегрузок над ней — это уже обычная функция с одной размытой сигнатурой из первого раздела, а не перегрузка.

Правила перегрузок

Чтобы перегрузки работали предсказуемо, держите в голове четыре правила.

  • Реализация не видна снаружи. Вызывающий код видит только сигнатуры-перегрузки. Аргумент должен подойти хотя бы под одну из них — иначе ошибка, даже если реализация технически его приняла бы.
  • Реализация должна быть совместима с каждой перегрузкой. Её параметры — шире (обычно объединение), а возвращаемый тип — таким, чтобы удовлетворять всем. Иначе компилятор пожалуется, что перегрузка несовместима с реализацией.
  • Порядок: от частного к общему. Перегрузки перебираются сверху вниз, и побеждает первая подходящая. Поэтому более узкую (точную) сигнатуру ставят выше более широкой.
  • Перегрузок нужно минимум две. Одна перегрузка + реализация не имеют смысла: если форма вызова одна, достаточно обычной сигнатуры без всей этой машинерии.

Первое правило легко проверить: реализация принимает string | number, но вызвать double с boolean всё равно нельзя — снаружи такой формы вызова просто нет.

Сигнатуры перегрузок Сигнатура реализации
Есть тело ❌ нет ✅ да
Видна вызывающему ✅ да ❌ нет
Сколько штук две и больше ровно одна
Зачем нужна что можно вызвать как это устроено внутри

Почему важен порядок

Когда одна перегрузка «шире» другой (её параметр принимает и то, что принимает соседняя), порядок начинает решать. Компилятор берёт первую подходящую сигнатуру, поэтому общая, стоящая сверху, перехватит вызовы, которые вы хотели отдать более точной.

Перегрузки методов

Тот же приём работает и для методов — в интерфейсах и псевдонимах типов. Метод просто перечисляют несколькими сигнатурами подряд; тела здесь нет вовсе — интерфейс лишь описывает форму, а реализацию даёт объект, который ему соответствует.

По той же схеме описывают перегруженный вызов в псевдониме типа: несколько строк вида (аргументы): результат внутри type Merge = { ... }. Такой тип задаёт функцию, которую можно вызвать двумя разными способами.

Когда перегрузки НЕ нужны

Перегрузки выглядят солидно, но чаще всего они избыточны и делают код многословнее, чем нужно. Прежде чем писать их, проверьте три более простых инструмента: параметр-объединение, необязательный параметр и дженерик.

Особенно часто вместо перегрузок нужен именно дженерик — когда тип результата не «ветвится» по типу входа, а просто повторяет его. Одна строка с <T> заменяет целый список перегрузок и вдобавок работает для любых типов, даже тех, что вы не перечисляли.

Что связывает вход и выход Чем описать
Результат всегда одного типа, а вход бывает разным параметр-объединение
Разница только в наличии аргумента необязательный параметр / значение по умолчанию
Тип результата = тип аргумента (проход насквозь) дженерик
Тип результата по-разному зависит от типа входа перегрузки

Правило большого пальца. Перегрузки уместны, только когда тип результата реально по-разному зависит от типов входа (как double: строка → строка, число → число, и внутри есть ветвление). Если же результат один и тот же тип или просто повторяет вход — берите объединение, необязательный параметр или дженерик: короче, понятнее, легче поддерживать.

Кратко

  • Зачем. Перегрузки нужны, когда тип результата по-разному зависит от типов аргументов, а одна сигнатура даёт лишь размытое string | number.
  • Синтаксис. Сначала несколько сигнатур-перегрузок без тела, затем одна реализация с телом и широкими параметрами.
  • Реализация скрыта. Вызывающий видит только перегрузки; аргумент обязан подойти под одну из них.
  • Совместимость. Реализация должна покрывать каждую перегрузку по параметрам и результату.
  • Порядок. Сверху вниз, побеждает первая подходящая — значит, точные сигнатуры ставят выше общих.
  • Минимум две. Одна перегрузка бессмысленна — хватит обычной сигнатуры.
  • Методы. Тот же приём работает для методов в интерфейсах и псевдонимах типов.
  • Чаще не нужны. Сначала попробуйте объединение, необязательный параметр или дженерик — обычно они проще и яснее.
