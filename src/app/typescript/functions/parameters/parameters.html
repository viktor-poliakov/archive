Параметры: опциональные и по умолчанию

Иногда заставлять того, кто вызывает функцию, передавать все аргументы — перебор. Приветствие можно и не указывать, количество по умолчанию равно единице, а комментарий часто пустой. У TypeScript для этого два инструмента: опциональные параметры (знак ?) — «аргумент можно опустить» — и параметры со значением по умолчанию (знак =) — «если не передали, подставится вот это». Похожи, но ведут себя по-разному; разберём оба и увидим, когда какой брать.

Опциональные параметры ?

Поставьте знак вопроса сразу после имени параметра — greeting?: string — и его станет можно не передавать при вызове. Функция greet(name: string, greeting?: string) согласится и на два аргумента, и на один: второй теперь необязателен.

Аналогия. Это как бумажный бланк-заявка. Поле «Имя» обязательное — без него заявку не примут. А «Комментарий (при желании)» помечено как необязательное: можно вписать, можно оставить пустым — бланк всё равно действителен. Знак ? — ровно та самая пометка «можно не заполнять».

Обратите внимание на диагностику компилятора. Раз аргумент могли не передать, то внутри функции тип greeting становится не просто string, а string | undefined. Поэтому в строгом режиме (strict) TypeScript не даёт сразу вызвать у него метод — вдруг там undefined.

Перед использованием — проверьте

Лечится это проверкой. Убедитесь, что значение действительно есть, — и компилятор сузит тип, убрав из него undefined. После if (greeting === undefined) в основной ветке остаётся чистый string, и все строковые методы снова доступны.

Подробно про то, как проверка «отрезает» undefined от типа, рассказано на странице Объединения и сужение. Тот же знак ? работает и на свойствах объектов — там он означает «поля может не быть».

Опциональные — только после обязательных

Есть жёсткое правило порядка: необязательный параметр не может стоять перед обязательным. Иначе позиционные аргументы стали бы неоднозначными — непонятно, какому слоту принадлежит переданное значение. Поставите ? раньше, чем нужно, — получите ошибку прямо в объявлении.

Параметры со значением по умолчанию =

Второй инструмент — задать параметру значение по умолчанию через знак равенства: greeting = 'Привет'. Если аргумент не передали, подставится это значение. Отдельно писать ? не нужно: наличие значения по умолчанию само делает параметр необязательным при вызове.

Приятный бонус — тип можно не писать вовсе. TypeScript выведет его из значения по умолчанию: у greeting = 'Привет' тип станет string. При желании тип указывают и явно (greeting: string = 'Привет') — это ровно то же самое, просто нагляднее.

Важно. Заметьте разницу с ?: внутри функции тип greeting здесь — просто string, а не string | undefined. Значение гарантировано (своё или по умолчанию), поэтому проверять на undefined и что-либо сужать не нужно. Это одно из главных практических отличий двух подходов.

Когда именно подставляется значение

Значение по умолчанию срабатывает в двух ситуациях: когда аргумент вообще не передан и когда на его месте явно стоит undefined. А вот null «пустотой» не считается — это осмысленное значение, и оно default не запускает (да ещё и не подходит по типу string).

Для опытных. Значение по умолчанию — это не константа, а выражение: оно вычисляется заново при каждом вызове, где аргумент опущен, и может ссылаться на параметры, объявленные левее. Так удобно строить одни аргументы из других.

? или значение по умолчанию

Оба знака делают аргумент необязательным — но дальше расходятся. Ключевой вопрос: что окажется внутри функции, если аргумент не передали. С ? это undefined (и тип придётся проверять), со значением по умолчанию — само это значение (проверять нечего). Сведём различия в таблицу.

Вопрос greeting?: string greeting = 'Привет'
Можно опустить аргумент? да да
Тип параметра внутри функции string | undefined string
Нужно проверять на undefined? да, иначе ошибка нет
Значение, когда аргумент не передан undefined 'Привет'

Отсюда простое правило выбора: если у параметра есть разумное значение по умолчанию — берите =, так удобнее и вам, и вызывающему коду. Если же «отсутствие» само по себе несёт смысл (поля просто нет) и вы готовы обрабатывать его в коде — берите ?.

Нельзя совмещать ? и =

Соблазнительно написать greeting?: string = 'Привет' — и попросить сразу «и необязательный, и со значением». Так нельзя: это ошибка синтаксиса. Значение по умолчанию и так делает параметр необязательным, поэтому ? оказывается лишним. Выбирайте что-то одно.

Обязательный параметр после параметра по умолчанию

Тут есть тонкость, отличающая = от ?. Необязательный ?-параметр обязан идти после всех обязательных — иначе ошибка. А параметр со значением по умолчанию TypeScript разрешает поставить и перед обязательным: само объявление компилируется без ошибок.

Вот только пользы от этого мало. Аргументы передаются по позиции, поэтому, чтобы добраться до обязательного параметра справа и при этом оставить значение по умолчанию слева, вызывающему коду придётся явно передать undefined на место «пропущенного» параметра. Выглядит неуклюже.

Почему так. В JavaScript нет «пропуска» позиционного аргумента: нельзя написать box(, 'ширина'). Единственный способ сказать «этот аргумент опускаю, возьми умолчание, а следующий вот» — это подставить undefined. Чтобы такого не случалось, параметры со значением по умолчанию держат в конце списка — тогда их можно просто не писать.

Кратко

  • ? — опциональный параметр: аргумент можно опустить. Внутри функции его тип — значение | undefined, поэтому перед использованием нужна проверка.
  • Опциональные параметры идут только после обязательных — иначе «A required parameter cannot follow an optional parameter».
  • = — значение по умолчанию: подставляется, когда аргумент не передан или равен undefined. Тип выводится из значения; внутри функции параметр — уже без undefined.
  • null значение по умолчанию не запускает — это осмысленное значение, а не «пусто».
  • Совмещать ? и = нельзя: значение по умолчанию само делает параметр необязательным.
  • Обязательный параметр после параметра со значением по умолчанию заставляет вызывающего передавать undefined вручную — поэтому параметры с умолчанием ставят в конце.
  • Выбор: есть разумное умолчание — берите =; «отсутствие» несёт смысл — берите ?.
