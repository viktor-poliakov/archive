TypeScript/Продвинутые типы/keyof

keyof

keyof — это «оглавление типа», или список подписей на ящиках картотеки. Представьте шкаф с ящиками, на каждом наклейка: «name», «age», «email». keyof берёт тип-объект и выдаёт объединение имён всех его ключей — как строковые литералы. Не сами значения из ящиков, а именно перечень наклеек. И, что критично, работает это в мире типов (на этапе компиляции): в собранном JavaScript никакого keyof нет.

Зачем нужен keyof

Начнём с боли, которую keyof лечит. Часто рядом с типом нужен перечень его допустимых полей: например, функция сортировки должна принимать только реальное имя колонки, а не любую строку. Напрашивается решение — выписать имена ключей руками, как объединение строковых литералов. Но такой список живёт отдельно от самого типа и быстро с ним «расходится».

Проблема ручного списка в том, что компилятор не видит связи между ним и типом Product. Добавили поле — список устарел, и никто об этом не предупредит. keyof убирает дублирование: он всегда берёт актуальный набор ключей прямо из типа-источника. Один источник правды вместо двух.

Базово: keyof User = 'name' | 'age'

keyof — это оператор над типами. Слева от него не значение, а тип: keyof SomeType. Результат — объединение строковых литералов, по одному на каждый ключ. Для типа с полями name и age получаем ровно 'name' | 'age'.

Держите в голове главную опору всего раздела: тип — это множество значений. Тип UserKey — это множество из трёх строк 'name', 'age', 'email'. Значение подходит под этот тип тогда и только тогда, когда оно равно одной из этих трёх строк. Ничего «магического» — просто множество допустимых имён.

keyof — это объединение литералов

Раз результат keyof — обычное объединение строковых литералов, к нему применимы все привычные операции над объединениями: можно исключить член через Exclude, оставить пересечение через Extract, использовать его в сужении. Это не какая-то особая сущность, а такой же union, как 'left' | 'right'.

Такой приём удобен, когда из полного набора полей нужно оставить «публичные» (без секретных) или, наоборот, только редактируемые. Вместо того чтобы переписывать список имён руками, вы получаете его из типа и уточняете операциями над объединениями.

keyof с индексной сигнатурой

Не у каждого типа есть фиксированный набор полей. Бывает индексная сигнатура — «любой строковый ключ ведёт к значению такого-то типа», например словарь очков игроков. Конкретных имён-ключей тут нет вовсе, поэтому keyof возвращает не список литералов, а string | number.

Почему number, а не только string? В JavaScript ключи объекта — всегда строки, но обратиться можно и по числу: obj[1] под капотом превращается в obj['1']. Поэтому для сигнатуры { [k: string]: number } компилятор считает допустимыми и строковые, и числовые ключи — отсюда string | number.

Практика: типобезопасный доступ и перебор ключей

Самое частое применение keyof — вместе с дженериками. Классика — функция «достать поле объекта по имени», которая должна принимать только существующие ключи и возвращать правильный тип поля. Ключ ограничивают через K extends keyof T (это мостик к ограничениям extends), а тип результата описывают индексным доступом T[K].

Обратите внимание: тип результата меняется в зависимости от ключа. Для 'name' вернётся string, для 'age' — number. А несуществующий ключ 'phone' отсекается ещё на компиляции. Всё это — без единого any и без ручных проверок в рантайме.

Перебор ключей: keyof против Object.keys

Новичков часто смущает вопрос: «Если keyof даёт ключи, почему Object.keys(obj) возвращает просто string[], а не точный набор?» Ответ снова упирается в разделение миров: keyof живёт в мире типов (компиляция), а Object.keys — это настоящая функция, работающая со значениями в рантайме.

Почему Object.keys шире. Из-за структурной типизации в переменную типа settings мог попасть объект и с лишними полями. Тогда точный набор ключей был бы неправдой, поэтому TypeScript намеренно возвращает string[]. Приведение as (keyof typeof settings)[] — это ваше обещание компилятору, что лишних полей нет; проверять его правдивость он не станет.

keyof вместе с typeof

Часто ключи нужны не от объявленного типа, а от уже существующего значения — объекта с настройками, картой роутов, конфигом. Тут в дело вступает оператор typeof в позиции типа: он берёт тип из значения. А дальше к этому типу применяют keyof. Читается справа налево: keyof typeof routes — «ключи типа значения routes».

keyof — только к типу, typeof — к значению. Вот главное различие двух операторов. Справа от keyof обязан стоять тип: keyof User — правильно, а keyof user (по переменной-значению) — ошибка компиляции. Справа же от typeof (в позиции типа), наоборот, ставят значение: typeof user. Именно поэтому, чтобы достать ключи из значения, операторы и соединяют в цепочку: сначала typeof превращает значение в тип, а затем keyof берёт у этого типа ключи — keyof typeof user. Написать keyof user напрямую нельзя.

Это один из самых полезных приёмов: единственный источник правды — сам объект routes, а тип имён выводится из него автоматически. Добавите роут — тип RouteName расширится сам. Тот же паттерн лежит в основе альтернативы enum через as const.

Два разных typeof. Здесь typeof стоит в позиции типа и достаёт тип из значения — это операция в мире типов. Не путайте с рантайм-оператором typeof x === 'string' в обычном выражении: тот возвращает строку и работает со значениями. Одинаковое слово, разные миры. Подробнее — на странице оператор typeof.

keyof от объединения: только общие ключи

А что, если применить keyof не к одному типу, а к объединению типов? Здравый смысл подсказывает верный ответ. Если значение — это «Article или Video», то мы заранее не знаем, что именно перед нами. Безопасно обращаться можно лишь к тем ключам, которые есть у обоих — иначе на статье не окажется поля durationSec, а на видео — поля body. Поэтому keyof (A | B) оставляет только общие ключи.

Легко перепутать. Объединение типов сужает набор ключей (остаётся пересечение), хотя само множество значений — расширяется. Это кажется парадоксом, но всё сходится: чем больше вариантов значения, тем меньше того, что гарантированно есть у каждого. Модель «тип — это множество» помогает не запутаться.

Коротко

  • keyof T — оператор в мире типов: берёт тип-объект и возвращает объединение имён его ключей как строковые литералы. «Оглавление типа».
  • Для interface User { name: string; age: number } результат — 'name' | 'age'. Это тип, а не значение: в рантайме его нет.
  • Результат — обычное объединение литералов, поэтому с ним работают приёмы объединений: Exclude, Extract, сужение.
  • Для индексной сигнатуры { [k: string]: number } получаем string | number (числовой ключ тоже допустим).
  • keyof (A | B) оставляет только общие ключи обоих типов — то, к чему безопасно обращаться в любом случае.
  • Главный практический приём — K extends keyof T для типобезопасного доступа к полю с типом результата T[K].
  • keyof на уровне типов ≠ Object.keys в рантайме: последний возвращает string[], потому что не гарантирует точный набор ключей.
  • Связка keyof typeof value достаёт имена ключей из готового значения — очень частый паттерн для конфигов и роутов.

Дальше по разделу: индексный доступ T[K] (достать тип по ключу), отображённые типы (пройтись { [K in keyof T]: ... } по всем ключам), оператор typeof и нюансы и подводные камни. Опора всего раздела — тип как множество значений и дженерики.
