TypeScript/Продвинутые типы/Индексный доступ

Индексный доступ

Вы наверняка сто раз писали obj['name'], чтобы достать значение из объекта. Индексный доступ в типах — ровно тот же жест теми же квадратными скобками, только этажом выше: obj['name'] достаёт ЗНАЧЕНИЕ по ключу, а User['name'] достаёт ТИП поля по ключу. Смысл один — «дай мне то, что лежит под этим ключом», — но obj[...] работает со значениями в рантайме, а User[...] — с типами на этапе компиляции. Ни строчки кода при этом не выполняется: мы просто спрашиваем у компилятора «какого типа это поле?».

Базово: User['name'] = string

Возьмём привычный тип пользователя и достанем тип одного его поля. В квадратные скобки кладём имя ключа — но не как строку-значение, а как литеральный тип-строку. Компилятор смотрит внутрь типа User, находит там ключ name и возвращает тип, который под ним записан.

Главное, что тут легко упустить: User['name'] — это выражение в мире типов. Оно не «читает поле объекта» (никакого объекта user вообще нет!) — оно спрашивает у типа User, какой тип объявлен под ключом name. Результат — тоже тип (string), а не значение.

И ещё одна ловушка для новичка: тип поля нельзя достать через точку. Точечная запись User.name — из мира значений, для типов она не работает. Только квадратные скобки:

Запомните различие. Точка (obj.name, User.name) — привычный синтаксис значений; для доступа к типу поля он не подходит. В мире типов работают только квадратные скобки User['name'].

Доступ по объединению ключей

В скобки не обязательно класть один ключ — можно передать объединение ключей. Тогда компилятор достанет тип каждого из этих полей и соберёт результаты в объединение. Логично: «дай тип поля name ИЛИ поля age» — значит, на выходе string или number.

А теперь — самая мощная и самая частая связка. Оператор keyof собирает все ключи типа в объединение (keyof User = 'name' | 'age'). Если этим объединением проиндексировать сам тип — User[keyof User], — мы достанем типы всех значений сразу. Получается «тип любого значения объекта User».

Ключи типа — тема оператора keyof, а как получить тип из готового значения — оператора typeof (частая пара — typeof объекта, затем keyof от него).

Массивы: Arr[number] = тип элемента

У массива тоже есть «ключ», по которому можно спросить тип, — это number. Ведь к элементам массива обращаются по числовым индексам (arr[0], arr[1], …), и у всех элементов тип один. Поэтому «индексный доступ по числовому ключу» Arr[number] даёт тип элемента.

Это очень удобный приём: если у вас уже есть тип массива данных, тип одного элемента не нужно объявлять отдельно — он берётся как Список[number]. Так один тип остаётся единственным источником правды.

Кортежи: по позиции и по number

Кортеж (tuple) — это массив с фиксированной длиной, где у каждой позиции свой тип. К нему индексный доступ работает даже точнее, чем к обычному массиву: можно спросить тип конкретной позиции по её номеру-литералу.

А если проиндексировать кортеж широким number (то есть «любой индекс»), получим объединение типов всех позиций. Сравните два случая — они отвечают на разные вопросы: Pair[0] — «что на нулевой позиции?», а Pair[number] — «что вообще может лежать на любой позиции?».

Вложенный доступ: T['a']['b']

Раз результат индексного доступа — снова тип, к нему можно применить квадратные скобки ещё раз. Скобки цепляются, как у значений obj['db']['port']: каждая пара спускает нас на уровень глубже. Так добираются до типа поля во вложенной структуре.

Обратите внимание на промежуточный шаг: Config['db'] сам по себе тоже полезный тип — целый объект { host: string; port: number }. Мы его не объявляли отдельно, а вытащили из Config.

Практика: один источник правды для типов

Главная ценность индексного доступа — не дублировать типы. Если тип поля можно достать из объявления, не переписывайте его руками: при изменении исходного типа копия молча устареет, а индексный доступ обновится сам.

Связку T[keyof T] удобно обобщить в переиспользуемый помощник. Так рождается частый утилитарный тип ValueOf<T> — «тип любого значения объекта T» (симметричная пара к keyof, который даёт ключи):

И, наконец, коронный номер — индексный доступ внутри дженерика. Функция «достать поле по ключу» описывается через параметр типа K, ограниченный как K extends keyof T, а возвращаемый тип — T[K]. Это даёт идеальную точность: для каждого ключа возвращается ровно тип его поля.

Этот приём — фундамент многих утилитарных типов и отображённых типов: почти везде, где нужно «пройтись по полям и что-то с их типами сделать», под капотом работает индексный доступ T[K].

Коротко

  • Индексный доступ T[K] достаёт тип по ключу — как obj[key] достаёт значение, но в мире типов, на этапе компиляции. Через точку (T.k) нельзя — только квадратные скобки.
  • По одному ключу: User['name'] = string. По объединению ключей — объединение типов: User['name' | 'age'] = string | number.
  • Связка с keyof: User[keyof User] = string | number — тип любого значения объекта. Обобщается в ValueOf<T> = T[keyof T].
  • Массивы: Arr[number] = тип элемента (string[][number] = string).
  • Кортежи: по номеру-литералу — тип позиции ([string, number][0] = string); по number — объединение всех позиций ([string, number][number] = string | number).
  • Скобки цепляются: Config['db']['port'] спускается вглубь вложенной структуры.
  • Зачем это: один источник правды — берите тип поля из объявления вместо ручного дубля; фундамент дженериков T[K], ValueOf и утилитарных типов.

Дальше по соседству: keyof (откуда берутся ключи), оператор typeof (тип из значения), отображённые типы (проход по всем ключам через T[K]) и условные типы. Опора всего раздела — модель «тип — это множество значений».
