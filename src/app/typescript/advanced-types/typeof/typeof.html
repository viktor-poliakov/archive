TypeScript/Продвинутые типы/Оператор typeof

Оператор typeof

typeof в позиции ТИПА — это «снять мерку с готовой вещи»: у нас уже есть значение (например, объект настроек), и мы хотим получить его тип, не выписывая его руками. Портной не придумывает размеры из головы — он прикладывает сантиметр к тому, что уже сшито. Так и здесь: тип не сочиняют заново, а «снимают» с существующего значения. И, что важно, снимают на этапе компиляции — в готовой программе этой операции уже нет.

Главное различие: два разных typeof

Прежде чем что-то делать, разведём по углам две вещи, которые пишутся одним словом и потому вечно путаются. В TypeScript слово typeof означает два совершенно разных инструмента, и они живут в разных мирах.

Первый — знакомый по обычному JavaScript рантайм-оператор. Он стоит внутри выражения (там, где вычисляются значения) и во время работы программы возвращает строку: 'string', 'number', 'object' и так далее. Это код, который реально исполняется в браузере.

Второй — typeof в позиции типа (его называют «запрос типа», type query). Он стоит там, где ожидается тип: после type, после двоеточия в аннотации. Он не исполняется никогда — он работает только для компилятора и возвращает тип. Именно про него вся эта страница.

Как отличить с одного взгляда. Смотрите, где стоит typeof. Если он в выражении и рядом сравнение (typeof x === '...') — это рантайм-оператор, результат строка. Если он после type или после двоеточия в аннотации типа — это запрос типа, результат тип. Дальше на странице речь только о втором.

Базовое использование: тип из значения

Начнём с самого простого случая — с объекта. Пусть у нас уже есть значение: пользователь с именем и возрастом. Мы не хотим отдельно, руками, описывать его тип — пусть компилятор «снимет мерку» сам.

Здесь type User = typeof user читается как «пусть User будет типом значения user». Компилятор смотрит на объект и выводит тип { name: string; age: number }. Литеральная строка 'Анна' при этом расширяется до string, а число 30 — до number: у обычного const-объекта поля можно переприсваивать, поэтому их типы берутся широкими.

Зачем это нужно: единый источник правды

Настоящая польза typeof раскрывается, когда одно и то же приходится описывать дважды — как значение и как тип. Классика жанра — объект конфигурации. Сначала посмотрим на боль ручного дублирования.

Две отдельные сущности — объект config и интерфейс ConfigManual — описывают одно и то же, но живут порознь. Направление важно. Обычно мы идём от типа к значению: сначала описываем interface, потом создаём объекты под него. typeof разворачивает стрелку — мы идём от значения к типу. Это удобно, когда «настоящий» источник данных — именно конкретное значение (конфиг, справочник, набор констант), а тип нужен лишь как его отражение.

Связка keyof typeof: имена ключей значения

Очень часто typeof идёт в паре с keyof. Логика простая: сначала typeof поднимает нас от значения к его типу, а затем keyof достаёт из этого типа имена ключей в виде объединения строк. Разберём по шагам.

Запись keyof typeof user читается справа налево: typeof user даёт тип { name: string; age: number }, а keyof от него — объединение 'name' | 'age'. Получилось множество допустимых имён ключей, вычисленное прямо из значения.

typeof для функций и массивов

typeof снимает мерку не только с объектов. Справа от него может стоять любое значение — в том числе функция или массив.

Мостик к «справочникам»: as const + typeof

Один из самых полезных паттернов в TypeScript — заменять enum обычным объектом или массивом, «замороженным» через as const. Здесь typeof — главный рабочий инструмент. Модификатор as const фиксирует значения как литералы (а не расширяет их до string/number), и тогда typeof «снимает» с них точную, литеральную мерку.

Комбинация (typeof Status)[keyof typeof Status] выглядит как матрёшка, но собирается из уже знакомых деталей: typeof Status — тип объекта, keyof typeof Status — его ключи, а индексный доступ по всем ключам достаёт объединение всех значений. Целиком этот приём (as const как замена enum) разобран на странице Альтернативы enum.

Частая ошибка: typeof ждёт значение, а не тип

Раз typeof «снимает мерку», то снимать её нужно с вещи — то есть со значения: переменной, функции, объекта. С типа мерку не снять, ведь у типа нет физического носителя. Поэтому справа от typeof должно стоять значение, а не имя типа.

Это прямое следствие модели «два мира». typeof в позиции типа — мостик из мира значений в мир типов: он берёт значение и отдаёт тип. Значит, на входе ему нужно именно значение. Развёрнуто эти и другие тонкости собраны на странице Нюансы и подводные камни.

Коротко

  • Два разных typeof. В выражении (typeof x === 'string') — рантайм-оператор, даёт строку. В позиции типа (type T = typeof x) — запрос типа, даёт тип. Разные миры, одно слово.
  • Суть — «снять мерку». typeof в позиции типа берёт готовое значение и возвращает его тип. Работает на этапе компиляции; в рантайме этой операции нет.
  • Единый источник правды. Опишите значение один раз, а тип выведите через typeof — тип обновится сам при изменении значения.
  • Связка keyof typeof. typeof даёт тип значения, keyof — имена его ключей: keyof typeof user = 'name' | 'age'.
  • Работает над функциями и массивами. typeof fn — сигнатура функции; (typeof arr)[number] — тип элемента массива.
  • Паттерн-справочник. as const фиксирует литералы, а (typeof Obj)[keyof typeof Obj] собирает из них объединение значений — удобная замена enum.
  • Справа только значение. typeof применяется к переменной/функции/объекту, но не к типу: typeof SomeType — ошибка.
