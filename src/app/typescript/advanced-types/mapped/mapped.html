Отображённые типы (mapped)

Отображённый (mapped) тип { [K in keyof T]: ... } — это «конвейер по ключам»: берём каждый ключ исходного типа и по одному правилу штампуем из него поле нового типа. Как пройтись по всем ящикам картотеки и на каждый повесить свежую бирку по единому образцу. Важно с самого начала: вся эта работа идёт в мире типов, на этапе компиляции — в готовом JavaScript от неё не остаётся ни следа, никакого «прохода по ключам» в рантайме нет.

Идея и синтаксис: { [K in keyof T]: T[K] }

Прежде чем собирать конвейер, посмотрим на две детали, из которых он состоит. Первая — keyof T: это объединение имён всех ключей типа. Вторая — индексный доступ T[K]: он достаёт тип значения по ключу (ровно как obj[key] достаёт значение, только в мире типов).

Теперь соединяем их. Запись [K in keyof T] читается как «пробегись переменной K по всем ключам из keyof T». Для каждого такого K мы описываем одно поле: слева — имя K, справа от двоеточия — тип этого поля. Модификаторы readonly и ? — добавляют

Первое, ради чего вообще нужны mapped-типы, — навесить один и тот же модификатор сразу на все поля, не переписывая тип руками. Модификатор ставится прямо перед скобкой [K in keyof T] (для readonly) или сразу после неё (для ?). Начнём с readonly — сделаем все поля доступными только для чтения:

Вместо ручного дублирования всех полей со знаком ? вы описываете правило один раз — и оно работает для типа любого размера.

Снятие модификаторов: -readonly и -?

Раз модификаторы можно добавлять, логично уметь их и снимать. Для этого перед модификатором ставят знак «минус»: -readonly убирает «только для чтения», а -? убирает необязательность (делает поле обязательным). Это зеркальные операции к прошлой секции.

Изменение типа значений

Ремаппинг ключей через as

Мы научились менять модификаторы и типы значений. Осталось самое мощное — переписывать сами имена ключей. Для этого после [K in keyof T] добавляют слово as и указывают, во что превратить ключ. Новое имя обычно собирают шаблонным литеральным типом: например, к каждому ключу приписать get и сделать первую букву заглавной. Заглавную даёт встроенная утилита Capitalize:

Одна тонкость, на которой спотыкаются все. В шаблоне мы пишем Capitalize<string & K>, а не просто Capitalize<K>. Причина: ключ K по типу может быть string | number | symbol, а Capitalize умеет работать только со строками. Пересечение string & K отбрасывает number и symbol, оставляя лишь строковую часть. Без него компилятор ругнётся:

❌ Type 'K' does not satisfy the constraint 'string'. — именно поэтому в реальном коде ремаппинга почти всегда встретите приём string & K.

Отсюда важный вывод: разобравшись в mapped-типах, вы одновременно поняли устройство почти всего набора утилит. За подробным разбором отдельных инструментов загляните к соседям: Partial / Required / Readonly, Pick / Omit. А «топливо» для mapped-типов — это keyof, индексный доступ T[K] и шаблонные литеральные типы для ремаппинга.

Коротко

  • Mapped-тип { [K in keyof T]: T[K] } — «конвейер по ключам»: пробегает переменной K по всем ключам keyof T и для каждого штампует поле по одному правилу. Работает в мире типов, на компиляции.
  • Правая часть (после двоеточия) — это тип значения. Оставили T[K] — копия; поставили boolean — все поля стали флагами; T[K] | null — все поля стали обнуляемыми.
  • Модификаторы добавляют: readonly [K in keyof T] делает поля неизменяемыми, [K in keyof T]? — необязательными.
  • Знак минус снимает: -readonly убирает «только для чтения», -? делает поля обязательными.
  • Ремаппинг ключей — через as: [K in keyof T as ...]. Новое имя удобно собирать шаблоном, например get${Capitalize<string & K>}. Пересечение string & K обязательно — иначе Capitalize подавится ключом-числом/символом.
  • Утилиты — это mapped-типы. Partial, Readonly, Required из стандартной библиотеки устроены буква в букву так, как мы их написали сами.

Рядом полезно освежить «топливо» конвейера: keyof, индексный доступ и шаблонные литеральные типы. Дальше — условные типы и infer, а типичные ошибки собраны в разделе нюансы и подводные камни. Базовая опора всего раздела — модель «тип — это множество значений».
