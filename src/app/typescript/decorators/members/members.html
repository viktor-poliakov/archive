Методы, свойства, аксессоры

До этого мы клеили наклейку на весь класс. Теперь спустимся внутрь и будем декорировать его отдельные части: методы, свойства (поля), геттеры и аксессоры. Здесь появляется самое полезное умение декораторов — обёртка: декоратор метода может «завернуть» метод в дополнительный слой, который срабатывает на каждый вызов (логирует, замеряет время, проверяет права). У каждого вида члена свои правила — что декоратор получает и что должен вернуть, — и мы разберём их по одному. Основы значка @ — на странице основы.

Декоратор метода: обёртка

Декоратор метода получает сам метод (аргумент value) и может вернуть другую функцию — обёртку. Тогда класс будет звать обёртку вместо исходного метода. Представьте секретаря перед кабинетом: он записывает каждого посетителя в журнал, потом пропускает его к начальнику и передаёт ответ обратно. Осторожно с this в обёртке

Обёртка должна пробросить this в настоящий метод — иначе метод не найдёт своих полей. Здесь легко ошибиться, поэтому запомните два правила: обёртка — это обычная function (не стрелка), а оригинал вызывается через value.apply(this, args):

Почему так. Стрелочная функция «запоминает» чужой this из места, где её создали, и не даст объекту подставить свой. А прямой вызов value(...args) вообще теряет this. Обычная function плюс .apply(this, args) честно передаёт тот объект, на котором метод позвали. Подробно про поведение this — на странице контекст this.

Полезный приём: @bound

Частая беда: метод «теряет this», когда его отрывают от объекта и передают как колбэк (например, onClick в обработчик события). Декоратор @bound решает это раз и навсегда. Он использует context.addInitializer — способ выполнить код при создании каждого объекта, когда this уже указывает на новый экземпляр:

Внутри addInitializer мы для каждого нового объекта намертво привязываем метод к нему через .bind(this). Теперь метод можно отрывать, передавать куда угодно — this всегда останется правильной кнопкой. Это тот же приём, что раньше писали руками в конструкторе (this.onClick = this.onClick.bind(this)), только вынесенный в аккуратную наклейку.

Когда именно срабатывает addInitializer. У декоратора члена (метода, поля) — при создании каждого объекта, и this внутри указывает на новый экземпляр (именно это нам и нужно для @bound). А если вызвать addInitializer из декоратора класса, он сработает один раз, когда класс полностью готов. Момент зависит от того, что декорируют.

Декоратор свойства (поля)

С полями всё устроено иначе, и это важно понять, чтобы не ждать от них лишнего. Декоратор поля не получает значение (аргумент value здесь всегда undefined) и не может обернуть чтение или запись. Аксессоры: перехват чтения и записи

Чтобы вклиниться в чтение и запись свойства (а не только в его начальное значение), в новых декораторах появилось ключевое слово accessor. Запись accessor health = 150 — это сокращение: язык сам заводит скрытое поле и пару геттер/сеттер к нему. Декоратор такого аксессора возвращает объект { get, set, init }, и можно подменить любую из трёх частей: как читать, как записывать, каким сделать начальное значение.

Соберём @clamp, который держит число в заданном диапазоне и при создании, и при каждой записи — удобно для здоровья игрока, громкости, процентов:

Что получает и что возвращает каждый вид

Сведём в таблицу, чтобы не держать всё в голове. Именно этим виды членских декораторов и отличаются друг от друга:

Вид Что получает (value) Что можно вернуть
Метод сам метод (функцию) новую функцию-обёртку (или ничего)
Геттер / сеттер функцию геттера/сеттера новую функцию (или ничего)
Свойство (поле) undefined (значения нет) функцию (initial) => новое (или ничего)
Аксессор (accessor) объект с get и set объект { get, set, init } (или ничего)

Во всех случаях у декоратора есть второй аргумент — context с полями kind ('method', 'field', 'getter', 'accessor'…), name, static, private, а также addInitializer и metadata. И у всех работает правило: вернул новое — заменит исходное, вернул undefined — оставит как было.

Как это выглядит в старом режиме

В экспериментальных декораторах метод декорируют иначе: функция получает (target, ключ, дескриптор) и меняет descriptor.value на месте, а не возвращает новую функцию:

Вывод. Идея та же — «подменить метод обёрткой», — но механика разная: новый декоратор возвращает функцию, старый правит дескриптор. Отдельного «декоратора поля-инициализатора» в старом режиме нет: там поля декорируют как свойства с сигнатурой (target, ключ). Разбор различий — на странице нюансы и подводные камни.

Коротко

  • Декоратор метода получает сам метод и может вернуть обёртку — функцию, которая срабатывает на каждый вызов (лог, замер, проверка). Оригинал внутри вызывают через value.apply(this, args).
  • Сам декоратор — раз, обёртка — много. Декоратор ставится при объявлении класса; установленная им обёртка работает на каждый вызов метода.
  • this в обёртке пробрасывайте через обычную function и .apply(this, args); стрелка и прямой вызов теряют контекст.
  • @bound через context.addInitializer намертво привязывает метод к объекту — решает проблему «потерянного this» в колбэках.
  • Декоратор поля не видит значения (value = undefined) и не оборачивает доступ — он лишь возвращает (initial) => новое, чтобы поправить начальное значение.
  • Аксессор (accessor) — единственный способ перехватить чтение и запись: декоратор возвращает { get, set, init }.
