Ключевое слово declare

Представьте табличку на двери кабинета: «Здесь принимает доктор Иванов». Табличка не создаёт доктора и не лечит пациентов — она лишь сообщает, что доктор есть и как его зовут. Ключевое слово declare — это ровно такая табличка для компилятора: «поверь на слово, вот эта штука уже где-то существует, и вот какого она типа». Никакого кода declare не создаёт — это объявление-обещание без реализации (по-научному — ambient-объявление, «объявление об окружении»). Как таможенная декларация: вы объявляете, что везёте вот это, — но сама декларация ничего не производит, она лишь фиксирует, что нечто есть.

Зачем это нужно

TypeScript проверяет только тот код, который видит. Но в реальной программе рядом всегда есть вещи, которые компилятор увидеть не может, а в момент работы они точно будут:

  • Глобальная переменная из тега <script> — например, библиотека аналитики подключена прямо в index.html и кладёт функцию gtag в глобальную область.
  • Значение, подставленное сборщиком — Vite или Webpack на этапе сборки заменяют слово VERSION (или __VERSION__) на реальную строку вроде "1.4.0".
  • API окружения — глобальные объекты, которые предоставляет платформа (браузер, Node.js, расширение), но которых нет в вашем исходнике.

Во всех этих случаях значение в рантайме есть, а в исходном коде оно нигде не объявлено — и компилятор честно жалуется:

Нам нужно описать эти имена, не создавая их: сказать компилятору «верь, что VERSION есть, это строка». Именно для этого и существует declare.

Как объявить: declare const

Самая частая форма — объявить переменную. Пишется как обычная const/let/var, но без присваивания значения: значение даст кто-то снаружи, а мы лишь обещаем тип.

Ключевая мысль. В строке declare const VERSION: string; нет ни =, ни значения. Это не «создать переменную VERSION», а «пообещать, что переменная VERSION где-то уже есть и её тип — string». Реализацию (реальное значение) поставляет сборщик, скрипт или другая часть системы.

Формы declare

Объявлять можно не только переменные. Общий принцип у всех форм один: пишем только тип (форму), без тела и без значения.

Отдельно подчеркнём функцию и класс: у declare-функции и declare-класса нет реализации — только сигнатура (имя, аргументы, типы). Мы обещаем, что функция есть и какая она, но не описываем, как она работает. Как только вы попытаетесь дописать тело — компилятор остановит:

Почему так. Табличка на двери сообщает «здесь принимает доктор Иванов», но не описывает, как именно он лечит. Точно так же declare function track(...) сообщает форму функции, а её «лечение» (тело) находится в другом месте. Тело внутри declare — это TS1183 «An implementation cannot be declared in ambient contexts».

declare ничего не компилирует

Вот что важнее всего понять про declare: он не попадает в собранный JavaScript ни одной строкой. Всё, что помечено declare, существует только на этапе компиляции — как знание для проверки типов — и бесследно исчезает из итогового .js.

Сравните с import type. У declare та же природа, что у «только типовых» конструкций: они нужны исключительно для проверки и стираются при компиляции. Разница в том, что import type тянет тип из другого файла, а declare — обещает, что нечто уже есть в окружении. Подробнее про стираемые импорты — на странице Импорт и экспорт типов.

Дополнить глобальную область: declare global

Иногда нужно не просто объявить новое имя, а дополнить уже существующий глобальный тип — например, добавить своё поле в Window. Для этого есть блок declare global: он открывает глобальную область и подмешивает в неё ваши объявления.

Здесь мы не создаём новый Window с нуля, а добавляем поле myWidget к тому Window, что уже описан в стандартной библиотеке. Это работает благодаря слиянию объявлений: два описания одного интерфейса Window объединяются в одно.

Важная тонкость. declare global работает только внутри файла-модуля — то есть файла, где есть хотя бы один import или export. В обычном скрипте (без импортов/экспортов) вы получите TS2669 «Augmentations for the global scope can only be directly nested in external modules...». Лечится одной строкой — пустым export {}, которая превращает файл в модуль, ничего наружу не экспортируя:

Практика: типизируем внешний скрипт аналитики

Соберём всё вместе на живом примере. В index.html подключён сторонний скрипт аналитики тегом <script>; он кладёт в глобальную область функцию gtag. В рантайме функция есть, но в нашем .ts-коде её никто не объявлял — и компилятор её не знает.

До объявления — красная волна Cannot find name 'gtag' и никакого автодополнения. После declare function gtag(...) — код компилируется, редактор подсказывает вызов, а типы аргументов проверяются как у обычной функции. Мы описали функцию, не написав её тела: реализацию поставляет подключённый скрипт.

Осторожно: declare — это обещание, а не проверка

У всей этой силы есть обратная сторона. declare — это ваше слово, которому компилятор верит безоговорочно. Он не проверяет, действительно ли объявленная вещь есть в рантайме. Если её там не окажется — программа упадёт, а компилятор при этом промолчит.

Та же природа, что у as. Приведение as и declare — родственники: оба говорят компилятору «поверь мне», оба ничего не проверяют в рантайме и оба стираются при компиляции. Поэтому правило одно: объявляйте через declare только то, что реально появляется в окружении. Обещание, которого рантайм не сдержит, — это отложенное падение. Подробнее о таких ловушках — на странице Нюансы и подводные камни.

Коротко

  • declare — это «табличка на двери»: объявление-обещание, что нечто уже существует в окружении, без создания кода. Научное имя — ambient-объявление.
  • Пишем только тип, без реализации. declare const VERSION: string; — без =; у declare function и declare class нет тела, только сигнатура (иначе TS1183).
  • Формы: declare const/let/var, declare function, declare class, declare namespace.
  • Ноль строк в .js. Всё, что помечено declare, существует только для компилятора и полностью исчезает из собранного кода.
  • declare global { … } дополняет глобальную область (например, добавляет поле в Window). Работает только в файле-модуле — добавьте export {}, если импортов/экспортов нет.
  • Это обещание, а не проверка. Если объявленной вещи в рантайме нет — падение, а компилятор молчит. Та же природа, что у as: объявляйте только то, что реально есть.
