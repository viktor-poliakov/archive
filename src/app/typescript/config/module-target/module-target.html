TypeScript/Конфигурация компилятора/module и target

module и target

TypeScript не выполняется сам по себе — он превращается в JavaScript, и уже тот запускается в браузере или Node. Две опции решают, каким получится этот JavaScript. target — «какого года выпуск» JavaScript: писать современно, но выдавать код, понятный даже старым браузерам, или оставлять всё как есть. module — «на каком языке модулей говорить»: как будут выглядеть import и export в готовом коде. Звучит абстрактно — поэтому сразу посмотрим на реальный результат компиляции.

target: какой версией JavaScript выдавать

target говорит компилятору, на какой стандарт JavaScript ориентироваться на выходе. Современный синтаксис (стрелки, классы, шаблонные строки) появился в языке не сразу; если целитесь в старое окружение, компилятор перепишет новый синтаксис на старый лад — это называют «понижением» (downleveling).

Коротко

  • TypeScript превращается в JavaScript. target и module определяют, каким этот JavaScript получится.
  • target — версия («год выпуска») JavaScript. Низкая (ES5) — компилятор переписывает современный синтаксис на старый (громоздко); современная (ES2020+) — оставляет почти как есть. Заодно задаёт набор встроенных типов (lib).
  • module — модульная система на выходе. CommonJS переписывает import/export в require; ESNext оставляет их как есть.
  • moduleResolution — как компилятор ищет файл по строке импорта. bundler — для фронтенда со сборщиком, NodeNext — для Node.
  • Берите готовые сочетания: браузер+сборщик (ESNext + bundler) или Node (NodeNext + NodeNext); module и moduleResolution должны согласовываться.
