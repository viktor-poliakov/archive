Пути и разрешение модулей

Когда вы пишете import ... from '...', кто-то должен по этой строке найти нужный файл. Этот процесс называется разрешением модулей. Сначала разберём, как компилятор ищет файлы по обычным путям, а потом — как настроить короткие псевдонимы (@/utils вместо ../../../utils) через опцию paths. И сразу предупредим о главной ловушке новичков, из-за которой «в редакторе всё зелёное, а запуск падает». Про соседнюю опцию moduleResolution см. страницу module и target.

Псевдонимы через paths

В большом проекте относительные пути превращаются в лесенки ../../../: их тяжело читать и они ломаются, стоит переместить файл. Опция paths заводит псевдонимы — короткие имена для папок. Договоримся, что @/ означает папку src:

Про baseUrl. В старых примерах вместе с paths почти всегда встречается опция baseUrl. В TypeScript 6.0 её объявили устаревшей — современным способом paths работают и без неё (нужно лишь подходящее moduleResolution, например bundler). Если видите baseUrl в чужом конфиге — это наследие, не пугайтесь.

⚠️ Главная ловушка: paths не переписываются

А теперь — важнейшее, из-за чего псевдонимы «загадочно ломаются». paths — это подсказка компилятору только на время проверки типов. В собранный JavaScript псевдоним попадает как есть: TypeScript его не расшифровывает. Посмотрите. Вот исходник с псевдонимом:

Чаще всего вопрос решается сам собой: в проекте со сборщиком (Vite, webpack) сборщик читает те же paths и подставляет реальные пути. Но если вы запускаете код прямо в Node без сборки, надёжнее использовать встроенные псевдонимы Node — поле imports в package.json. Их имена начинаются с #, и Node расшифровывает их сам:

Обратите внимание: здесь псевдоним указывает на папку dist, а не src. Это не опечатка: Node запускает уже собранный JavaScript из dist, поэтому и путь ведёт туда. А paths в tsconfig.json смотрели на исходники в src, потому что работают на этапе проверки типов. Разные инструменты — разные папки.

Правило. paths из tsconfig.json — удобство на время разработки и проверки типов; они не волшебные и в рантайме сами не работают. Псевдонимы должен расшифровать сборщик, тест-раннер или (для чистого Node) поле imports в package.json. Забыли про это — получите ERR_MODULE_NOT_FOUND.

Коротко

  • Разрешение модулей — как компилятор находит файл по строке импорта. Относительный путь (./, ../) ищется рядом; голое имя (zod) — в node_modules.
  • paths — псевдонимы для папок (@/* → ./src/*): вместо хрупких ../../../ пишем короткое @/utils/date.
  • baseUrl устарел в TypeScript 6.0 — современные paths работают без него (с подходящим moduleResolution, например bundler).
  • Главная ловушка: paths действуют только при проверке типов — в собранный код псевдоним попадает как есть, и в рантайме будет ERR_MODULE_NOT_FOUND, если его никто не расшифровал.
  • Расшифровывает псевдонимы сборщик (Vite/webpack), тест-раннер или — для чистого Node — поле imports (#-псевдонимы) в package.json.
