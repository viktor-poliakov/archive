TypeScript/Классы/readonly и static

readonly и static

Два независимых модификатора, которые часто путают. readonly — это «залито в бетон после сборки»: поле можно поставить один раз (при создании объекта), а дальше — не переставить. static — это «общая доска объявлений на весь класс»: такой член один на всех, он принадлежит самому классу, а не каждому объекту по отдельности. Разберём обе идеи с нуля, на реальных примерах: пользователь, банковский счёт, круг. Если классы как таковые ещё в новинку, загляните в основы классов в JS.

readonly-поля: поставил раз — не переставишь

Обычное поле класса можно менять сколько угодно раз. Иногда это опасно: например, id пользователя или номер счёта не должны меняться после создания — если их случайно перезапишут, поедет вся логика. Модификатор readonly («только для чтения») как раз для этого: он разрешает записать значение в поле только при «сборке» объекта, а потом делает поле неизменяемым.

Записать в readonly-поле можно ровно в двух местах: прямо в объявлении (значение общее для всех объектов) или в конструкторе (у каждого объекта своё). Читать — где угодно и сколько угодно.

А вот попытка переприсвоить readonly-поле после создания объекта — снаружи или даже из обычного метода — это ошибка компиляции. Бетон уже застыл:

Тонкость. readonly «поверхностный»: он запрещает переставить саму ссылку, но не запрещает менять содержимое объекта или массива, на которые поле указывает.

readonly и const — в чём разница

Новички часто спрашивают: чем readonly отличается от const, ведь оба «запрещают менять»? Разница в том, что именно они защищают. const — это про переменную: нельзя переприсвоить саму переменную. readonly — это про свойство объекта или класса: нельзя переприсвоить поле. Это разные уровни, и один другой не заменяет.

Важно. readonly — чисто «типовая» защита: при компиляции модификатор стирается, и в готовом JS никакого запрета не остаётся. Это страховка для вас и коллег на этапе написания кода, а не броня в рантайме.

static-члены: принадлежат классу, а не объекту

Обычные поля и методы принадлежат каждому объекту по отдельности: у Анны свой баланс, у Бориса — свой. Но иногда данные логично держать на весь класс сразу: например, счётчик «сколько всего пользователей создано». Заводить его копию в каждом объекте бессмысленно — счётчик должен быть один общий. Для этого и нужен static: такой член живёт на самом классе, как объявление на общей доске.

Раз static-член лежит на классе, то и обращаться к нему нужно через имя класса — User.total. А вот через экземпляр он недоступен: у объекта этого поля просто нет.

Запомните направление. Class.member — правильно; instance.member для static — ошибка «Property does not exist on type». Доска объявлений висит на стене (класс), а не в кармане у каждого сотрудника (объект).

static-методы: фабрики и утилиты

Статическими бывают не только поля, но и методы. Такой метод вызывают тоже через класс (Class.method()), и у него нет this конкретного объекта — ведь он не привязан ни к одному экземпляру. Два самых частых применения — фабрики и утилиты.

static + readonly: константы класса

Два модификатора отлично сочетаются. static readonly вместе дают константу класса: значение одно на весь класс (это static) и его нельзя переприсвоить (это readonly). Классический пример — математические или конфигурационные константы вроде числа PI.

Читается такая константа через имя класса (Circle.PI), а любая попытка её перезаписать ловится компилятором. Это удобнее, чем прятать «магическое число» где-то в коде метода: константа на виду, у неё есть имя, и она гарантированно неизменна.

instance и static рядом: у каждого своё, общее — одно

Соберём всё вместе на банковском счёте. У каждого счёта свои владелец и баланс — это обычные (instance) поля, они хранятся в каждом объекте отдельно. А имя банка и общее число открытых счетов — общие для всех, это static-члены, они хранятся один раз на самом классе.

Коротко

  • readonly — поле «только для чтения»: записать можно в объявлении или в конструкторе, переприсвоить после — ошибка «Cannot assign to ... because it is a read-only property».
  • readonly поверхностный: защищает саму ссылку, но не содержимое объекта/массива, на который она указывает.
  • const и readonly — разные уровни: const запрещает переприсвоить переменную, readonly — поле. У полей класса «своего const» не бывает.
  • static — член принадлежит классу, а не объекту. Обращение через Class.member; через экземпляр — ошибка «Property does not exist on type».
  • static-методы — общие инструменты класса без this объекта: фабрики (User.createGuest()) и утилиты (MathUtils.clamp(...)).
  • static readonly вместе — константа класса: одна на всех и неизменяемая (Circle.PI).
  • Оба модификатора живут только в типах: при компиляции они стираются и в готовом JS запретов не оставляют.

Рядом полезно посмотреть модификаторы доступа (public/private/protected) и параметры-свойства, где readonly можно объявить прямо в конструкторе. Как работают статические и приватные члены на уровне JavaScript — на странице статика и приватность в JS.
