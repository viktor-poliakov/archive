TypeScript/Классы/Основы

Основы

Класс — это чертёж (или форма для выпечки), а объекты (по-другому — экземпляры) — это готовые изделия по этому чертежу. Устройство у всех одинаковое, а наполнение — разное: из одной формы для кексов выходит десяток кексов одинаковой формы, но с разной начинкой. Класс описывает, как устроена вещь один раз, а дальше по нему штампуют сколько угодно объектов.

Что такое класс

Представьте задачу из списка дел. У неё есть данные: название («Купить хлеб») и признак «сделана или нет». И есть поведение: задачу можно отметить выполненной, переименовать, показать в списке. До классов данные обычно лежали в одном месте (в объекте), а функции, которые с ними работают, — в другом, и связать их можно было только на словах.

Класс наводит порядок: он складывает данные и поведение в один тип. Данные внутри класса называют полями (это переменные, живущие внутри объекта), а поведение — методами (это функции, живущие внутри объекта). Всё, что относится к задаче, теперь лежит рядом и путешествует вместе.

Если классы в JavaScript вам ещё в новинку, начните с базовой страницы JS: классы, основы — там разобрана сама механика без типов. Здесь мы смотрим на то же самое глазами TypeScript: добавляем к полям и методам типы, чтобы компилятор ловил ошибки заранее.

Синтаксис: поля, конструктор, методы

Опишем класс Task — задачу. Разберём его по частям сразу после кода.

Что здесь есть:

  • Поля title: string и done: boolean — это данные каждой задачи. В отличие от чистого JavaScript, у поля указан тип — компилятор проследит, чтобы в title не попало число, а в done — строка.
  • Конструктор constructor(...) — особый метод, который автоматически срабатывает в момент создания объекта. Его задача — заполнить поля стартовыми значениями. Это «сборочный цех» изделия.
  • Метод toggle() — обычная функция внутри класса, описывающая поведение. Запись : void означает «ничего не возвращает».
  • this — ключевое слово, которое внутри класса указывает на текущий экземпляр: тот самый объект, который сейчас создаётся или у которого вызвали метод. Через this.title мы обращаемся к полю именно этого объекта.

Про this подробнее. Слово this нередко сбивает новичков с толку — что именно оно значит, зависит от того, как вызвали метод. Полный разбор — на страницах JS: что такое this и Типизация this. Для старта достаточно правила: внутри метода this — это «я», текущий объект.

Создание объекта: new Task(...)

Сам класс — это только чертёж, он ничего не хранит. Чтобы получить настоящий объект (по-другому — экземпляр), по чертежу нужно «изготовить изделие». Делается это оператором new: он запускает конструктор, передаёт ему аргументы и возвращает готовый объект.

Мы создали два объекта из одного класса. Оба устроены одинаково — у обоих есть title, done и метод toggle. Но это два независимых экземпляра со своим наполнением: изменили buyBread — callMom остался нетронутым. В этом вся суть: один чертёж, много самостоятельных изделий.

Методы и this

Методы — это поведение объекта, а this — их связь с данными конкретного экземпляра. Добавим к Task ещё пару методов: rename (переименовать) и describe (показать в виде строки).

Когда мы пишем task.rename('...'), внутри метода this становится равен task — тому объекту, слева от точки. Поэтому this.title = newTitle меняет название именно у task, а не у какой-то другой задачи. Метод describe тем же this читает поля и собирает из них строку. Один и тот же код метода обслуживает любой экземпляр — this каждый раз подставляет нужный.

Аналогия. Представьте инструкцию «поставь свою подпись». Текст инструкции один на всех, но «своя» у каждого человека — своя. Вот this и есть это «своя/свой»: внутри метода оно указывает на того, кто сейчас его выполняет.

Наследование: extends и super(...)

Часто разные классы имеют общую часть. У кошки, собаки и попугая есть имя и умение подавать голос — это общее. Переписывать это в каждый класс заново скучно и опасно (легко разойтись). Наследование позволяет вынести общее в базовый класс, а остальным — «унаследовать» его и добавить своё.

Теперь сделаем Dog наследником Animal через ключевое слово extends. Собака автоматически получит поле name и метод speak, а мы добавим ей своё поле breed (порода) и по-своему научим её «говорить».

Ключевой момент — вызов super(name) в конструкторе наследника. super — это ссылка на базовый класс, а super(...) — вызов его конструктора. Мы как бы говорим: «пусть сначала Animal соберёт свою часть (заполнит name), а потом я допишу своё (breed)». Порядок важен: обращаться к this в наследнике можно только после super() — до этого объект ещё «не собран» базой.

Иногда новую версию метода хочется не заменить полностью, а дополнить — вызвать старую и добавить к ней своё. Для этого есть super.метод(): он зовёт версию метода из базового класса.

Различайте два «super». super(...) (со скобками сразу после) — это вызов конструктора базы, он допустим только внутри конструктора. А super.speak() — вызов метода базы из любого метода наследника. Разные вещи с похожим написанием.

Переопределение и override

Когда наследник задаёт свою версию метода, уже существующего в базе, это называют переопределением. В этом проекте включена строгая опция noImplicitOverride, поэтому такой метод обязан быть помечен ключевым словом override. Это не формальность, а защита: override прямо заявляет «я осознанно перекрываю метод базы», и компилятор проверяет, что метод там действительно есть.

Правило работает в обе стороны:

  • Забыли override на методе, который перекрывает базовый → ошибка «This member must have an 'override' modifier…». Компилятор напоминает, что вы, возможно, случайно затёрли метод родителя.
  • Поставили override на метод, которого в базе нет (например, опечатались в имени) → ошибка «This member cannot have an 'override' modifier…». Значит, вы не переопределяете, а создаёте новый метод — и, скорее всего, из-за опечатки.

Зачем это нужно. Без override легко попасть в ловушку: переименовали метод в базовом классе — а в наследнике остался старый метод, который теперь ничего не перекрывает и молча живёт сам по себе. С override компилятор сразу подсветит рассинхрон. Обо всех тонкостях наследования — на странице Нюансы и подводные камни.

Конструктор наследника обязан звать super()

Ещё одно жёсткое правило: если у наследника есть свой конструктор, он обязан вызвать super(...), причём до первого обращения к this. Логика простая: пока базовый класс не собрал свою часть объекта, this ещё не готов, и трогать его нельзя.

Если наследник не объявляет собственный конструктор вовсе, TypeScript использует конструктор базового класса автоматически, и вызывать super() вручную не нужно — как в примере с Dog из раздела про super.speak(). Тонкости работы this при этом описаны на странице JS: потеря контекста.

Класс — это ещё и тип

Важная идея, которая отличает классы в TypeScript от классов в чистом JavaScript: объявляя класс, вы одновременно объявляете тип с тем же именем. То есть Task — это и «фабрика объектов» (её зовут через new), и полноценный тип, которым можно аннотировать переменные, параметры и результаты функций.

Обратите внимание на последнюю строку примера. TypeScript сравнивает типы по форме (это называют структурной типизацией): если у обычного объекта те же поля тех же типов, он подойдёт под тип Task, даже если создан без new. Такой объект несёт только данные — методов вроде toggle у него нет. Подробнее о том, что «тип — это множество подходящих значений», — на странице Подтипы и супертипы.

Класс — удобный, но не единственный способ описать форму объекта. Когда нужна только форма без поведения и без new, часто берут интерфейс. Классы и интерфейсы отлично работают вместе — класс может пообещать соответствовать интерфейсу (об этом — на странице Реализация интерфейсов).

Коротко

  • Класс — чертёж: он объединяет данные (поля) и поведение (методы) в один тип. Объект (экземпляр) — готовое изделие по чертежу, создаётся через new.
  • Конструктор срабатывает при создании объекта и заполняет поля; this внутри класса — это «я», текущий экземпляр.
  • Методы — функции внутри класса; через this они читают и меняют поля именно того объекта, у которого вызваны.
  • Наследование: class Dog extends Animal даёт собаке поля и методы базы. Свой конструктор наследника обязан позвать super(...) до обращения к this.
  • super.метод() вызывает версию метода из базового класса — чтобы дополнить, а не выбросить поведение родителя.
  • Переопределение требует override (включён noImplicitOverride): забыли — ошибка; поставили на несуществующий в базе метод — тоже ошибка.
  • Класс — это ещё и тип: именем класса можно аннотировать переменные и параметры (const t: Task).

Дальше логично разобрать модификаторы доступа (public, private, protected) — они решают, что у объекта видно снаружи, а что спрятано внутри. Если база JS-классов ещё шатается, загляните в JS: классы, основы и JS: наследование. А когда захочется описывать форму объектов без new — вам на страницу Интерфейсы.
