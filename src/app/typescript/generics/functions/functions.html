Дженерик-функции

В Основах мы познакомились с одним параметром типа <T>. Теперь разберём дженерик-функции подробнее: как использовать несколько параметров типа сразу и как компилятор сам выводит их из аргументов. Хорошая аналогия для этой страницы — функция map как конвейер-переработчик: на вход едет ящик яблок (тип T), а по заданному правилу выезжает ящик долек (тип U).

Напоминание: один параметр типа

Начнём с уже знакомого. Параметр типа T — это «переменная для типа»: он подставляется в момент вызова и связывает вход с выходом. Какой тип передали — такой же и вернётся.

Несколько параметров типа: <T, U>

Параметров типа может быть не один, а сколько нужно — их перечисляют через запятую в угловых скобках. Классический пример — функция pair, склеивающая два значения возможно разных типов в кортеж. Первому значению соответствует параметр K, второму — V, и они независимы: не обязаны совпадать.

Обратите внимание: K и V вывелись каждый из своего аргумента. Это и есть суть нескольких параметров типа — они держат независимые «ниточки» между разными входами и выходами.

Как компилятор выводит типы из аргументов

Откуда компилятор берёт K и V? Он смотрит на аргументы по позициям: что реально передали на первое место, что на второе, — и подставляет их типы. Это как умный кассир: он не спрашивает «а какого сорта ваш товар?», а просто считывает штрихкод того, что вы положили на ленту.

Классика: map, filter, pluck

Дженерик-функции сияют на обработке коллекций. Три «рабочие лошадки» — map, filter, pluck — встречаются в реальном коде постоянно.

map — тот самый «конвейер-переработчик»: принимает массив элементов типа T и правило переработки (x: T) => U, отдаёт массив результатов типа U. Здесь два параметра типа не случайно: вход и выход — разные сорта.

filter — наоборот, «сито»: часть элементов оставляет, часть выбрасывает, но тип не меняет. Вход T[] — и выход T[]. Поэтому здесь достаточно одного параметра типа.

Дженерик как тип переменной

До сих пор <T> стоял у объявления функции. Но дженерик-сигнатуру можно записать и как тип переменной — тогда угловые скобки ставят прямо внутри типа, перед списком аргументов: <T>(x: T) => T.

Когда вывод не срабатывает — указываем явно

Вывод хорош, пока компилятору есть на что смотреть. Но иногда типа неоткуда взять — и тогда результат разочаровывает. Самый частый случай — пустой массив: выводить T не из чего, и он «схлопывается» в never (пустое множество значений).

Стрелка или function: где ставить <T>

Место для параметра типа зависит от того, как записана функция. У обычного объявления function он идёт сразу после имени; у стрелочной функции — перед списком аргументов. В обычных .ts-файлах оба варианта равноправны.

Тонкость для .tsx (React). В файлах с JSX голое <T> у стрелки компилятор принимает за открывающий тег. Лечится запятой-подсказкой <T,> либо переходом на обычное function-объявление, где такой неоднозначности нет.

Дженерик вместо перегрузки — коротко

Если тип результата просто повторяет тип аргумента (значение проходит «насквозь», без ветвления по типу), то дженерик короче и точнее, чем перегрузки.

Важная оговорка: дженерик заменяет перегрузки только когда нет разного поведения по типу. Если результат по-настоящему зависит от того, строка пришла или число (разные поля, разная логика), нужны именно перегрузки — их подробный разбор на отдельной странице Перегрузки.

Коротко

  • Параметров типа может быть несколько (<T, U>, <K, V>) — они независимы и держат отдельные «ниточки» между входами и выходами.
  • Компилятор выводит типы из аргументов по позициям — как кассир по штрихкоду. Явно указывать <...> обычно не нужно.
  • map<T, U> меняет тип (T → U), filter<T> — сохраняет (T → T). U вычисляется из того, что вернул колбэк.
  • Дженерик-сигнатуру можно записать как тип переменной (<T>(x: T) => T) и дать ей имя через type (Mapper<T, U>).
  • Когда вывести T не из чего (пустой массив → never[]) или вывод неточен — указывайте тип явно в угловых скобках.
  • Где ставить <T>: у function — после имени, у стрелки — перед скобками (в .tsx писать <T,>). Дженерик заменяет перегрузку, только если тип результата повторяет тип аргумента.

Дальше — как ограничить T, чтобы у него были нужные поля: Ограничения (extends) (там же типобезопасный pluck через keyof). Затем — значения по умолчанию и дженерики в классах и интерфейсах. Типичные ошибки собраны в разделе Нюансы и подводные камни.
