TypeScript/Объединения и сужение/Сужение типов

Сужение типов

Объединение вроде string | number — это «широкое» множество: значение может оказаться и строкой, и числом. Но работать хочется с чем-то конкретным. Сужение типов (narrowing) — это процесс, в котором вы проверками доказываете компилятору, какой именно тип перед вами прямо сейчас, а он в ответ разрешает пользоваться специфичными для этого типа возможностями.

Зачем это нужно

Пока значение имеет тип-объединение, TypeScript разрешает трогать только те свойства и методы, которые есть у всех членов union сразу. Ведь компилятор не знает заранее, строка там сейчас или число, — а значит, обязан защитить вас от вызова того, чего у одного из вариантов может не быть.

Аналогия: «сначала проверь — потом действуй». На странице Подтипы и супертипы был образ: «где нужен фрукт — яблоко сойдёт, а где нужно яблоко — не всякий фрукт подойдёт». Union — как ящик с надписью «фрукт»: там может лежать что угодно из фруктов. Прежде чем очистить его «как банан», надо заглянуть и убедиться, что это правда банан. Сужение — и есть тот самый взгляд в ящик.

В модели «тип — это множество значений» сужение выглядит как отсечение части множества. Проверка typeof id === 'string' разбивает исходное множество string | number на две части: то, что прошло проверку (строки), и то, что не прошло (числа). Внутри каждой ветки остаётся только своя половина.

Анализ потока управления

Магия в том, что вам не нужно ничего сообщать компилятору вручную. TypeScript сам читает ваш код сверху вниз и отслеживает проверки — это называется анализом потока управления (control flow analysis). Попав внутрь ветки if, компилятор помнит, какое условие туда привело, и автоматически уточняет тип переменной именно в этом месте.

Обратите внимание: в ветке else тип сузился до number, хотя мы про число ничего не проверяли. Логика простая: раз значение — из множества string | number и это не строка, остаётся единственный вариант — число. Компилятор умеет так рассуждать.

Способ 1: typeof — для примитивов

Оператор typeof возвращает строку с названием типа значения. TypeScript знает все возможные результаты и по каждому из них сужает тип. Это главный инструмент для примитивов: строк, чисел, булевых значений.

Возможных строковых результатов у typeof ровно восемь. Вот они и типы, к которым приводит сужение:

typeof x вернёт Примеры значений Тип после сужения
'string' 'hello', '' string
'number' 42, 3.14, NaN number
'boolean' true, false boolean
'bigint' 10n bigint
'symbol' Symbol('id') symbol
'undefined' undefined undefined
'function' console.log тип функции
'object' { id: 1 }, [1, 2], null объект или null!

Подвох: typeof null === 'object'

Последняя строка таблицы — знаменитая ловушка JavaScript: у null тоже typeof равен 'object'. Значит, проверка typeof x === 'object' пропустит внутрь и null, и массив, и обычный объект. Для отсева именно null надёжнее прямое сравнение.

Способ 2: проверка на истинность (truthiness)

Условие if (x) пропускает внутрь только truthy-значения. Это удобный способ одним движением отсечь null и undefined: в ветке остаётся «настоящее» значение.

Но здесь прячется классическая ошибка. Falsy — это не только null и undefined. Пустая строка '', число 0 и NaN тоже falsy — и тоже «провалят» проверку if (x), хотя это совершенно валидные значения.

Правило. Проверку на истинность применяйте, когда «пустое» и «нулевое» для вас одно и то же. Если же 0 или '' — это осмысленные значения, сужайте явным сравнением: x !== undefined, x !== null.

Способ 3: равенство — ===, !== и switch

Сравнение с конкретным значением тоже сужает тип. Особенно ярко это работает с литеральными типами: убрав из union один из его литералов, вы оставляете остальные.

Способ 4: оператор in — по наличию свойства

Когда члены union — объекты с разным набором полей, различать их удобно оператором in: он проверяет, есть ли у объекта свойство с таким именем. Типичный кейс — ответ API, у которого «успех» и «ошибка» имеют разную форму.

Проверка 'data' in res означает «у этого объекта есть поле data». Поскольку data объявлено только в ApiSuccess, TypeScript сужает res до ApiSuccess внутри if и до ApiError — в else.

Способ 5: instanceof — для экземпляров классов

Если в union участвуют классы, проверяйте их через instanceof. Оператор отвечает на вопрос «создан ли объект этим классом (или его наследником)».

Важно: instanceof учитывает цепочку наследования — err instanceof Error будет true и для ValidationError, ведь тот расширяет Error. Поэтому более конкретные классы проверяйте раньше базовых.

Способ 6: Array.isArray — для T | T[]

Частая ситуация: значение приходит либо одним элементом, либо массивом элементов. Отличить массив от одиночного значения помогает встроенный Array.isArray — typeof тут бесполезен, ведь массив тоже 'object'.

Способ 7: сужение через присваивание

Тип уточняется не только в проверках. Как только вы присвоили переменной конкретное значение, TypeScript в дальнейшем коде считает её типом тип этого значения — при том что объявленный (широкий) тип он тоже помнит и разрешит присвоить другой член union позже.

Приём: early return (guard clause)

Сужение особенно красиво сочетается с ранним выходом из функции. Вместо «лесенки» вложенных if отсекайте неподходящие случаи return-ом в самом начале. Каждый такой сторожевой if сужает тип для всего кода ниже — и основная логика идёт ровным, невложенным «счастливым путём».

После if (!user) return; компилятор знает: раз мы дошли до следующей строки, user — точно не null. Дальше он уже сужен до User. Так сужение делает код одновременно и безопаснее, и чище.

Исчерпывающая проверка через never

Когда вы перебираете все члены union в switch, полезно застраховаться на будущее: пусть компилятор сам напомнит, если однажды в union добавят новый вариант, а обработать его забудут. Трюк — присвоить «недостижимое» значение переменной типа never.

Пока все case разобраны, в default значение сужено до never (пустого множества) — и присваивание проходит. Стоит добавить в Shape новый вид фигуры и забыть про него — в default «дотечёт» этот необработанный тип, он уже не never, и компилятор подсветит ошибку. Подробный разбор этого приёма — на странице Размеченные объединения.

Когда встроенных проверок мало

typeof, in, instanceof покрывают большинство случаев, но не все — например, «это непустая строка» или «это валидный объект пользователя» встроенными операторами не выразить. На такой случай в TypeScript есть функции-предикаты: вы пишете свою проверку, а в её сигнатуре указываете x is T — и компилятор начинает доверять ей при сужении.

Это большая отдельная тема — как устроен предикат is, чем он отличается от обычного boolean и как не соврать компилятору. Ей посвящена страница Проверки типов (type guards) и продолжение — Пользовательские type guards.

Коротко

  • У значения-union доступны только общие члены. Чтобы добраться до специфичных, тип нужно сузить — доказать компилятору, что перед вами конкретный вариант.
  • Сужение — это отсечение части множества: движение от широкого union к более узкому подтипу. Прямое продолжение модели «тип — это множество».
  • TypeScript сам следит за проверками — это анализ потока управления: внутри ветки тип уже уточнён, за её пределами снова широкий.
  • Инструменты сужения: typeof (примитивы), проверка на истинность, ===/!== и switch, in (по свойству), instanceof (классы), Array.isArray (T | T[]), а также присваивание.
  • Помните ловушки: typeof null === 'object' и falsy-значения 0, '', NaN при проверке на истинность.
  • Early return с сужением делает код плоским и читаемым; проверка через never ловит незакрытые ветки при расширении union.
