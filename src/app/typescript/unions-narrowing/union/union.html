Объединения (union)

Объединение (union type) — это способ сказать: «здесь будет значение или одного типа, или другого». Записывается через вертикальную черту: string | number. Если помнить, что тип — это множество значений, то union читается буквально как объединение множеств: он охватывает всё, что входит в любой из своих членов, а значит шире каждого из них.

Идея: «или A, или B»

Иногда переменная не обязана быть строго одного типа. Идентификатор в базе бывает то числом, то строковым кодом. Поле ввода принимает то логин-строку, то числовой id. Функция-поиск возвращает то найденный объект, то «ничего». Для всех таких случаев в TypeScript есть объединение.

Аналогия. Представьте ячейку торгового автомата с надписью «принимаю монету или банкноту». В неё влезет и то, и другое — но в каждый конкретный момент лежит что-то одно. Тип Coin | Banknote — ровно про это: значение будет одним из вариантов, а каким именно — выяснится в рантайме.

Свяжем это с моделью множеств из страницы Подтипы и супертипы. Каждый тип — это множество значений. Объединение A | B — это объединение множеств (по-математически A ∪ B): в него входят все значения из A плюс все значения из B. Поэтому union всегда шире каждого своего члена и является их супертипом: и A, и B целиком помещаются внутрь A | B.

Литеральные объединения

Членами union могут быть не только «широкие» типы вроде string, но и конкретные литеральные типы — отдельные значения. Так описывают «одно из нескольких допустимых»: режим сортировки, статус заказа, размер футболки. Это одно из самых полезных применений union на практике.

Компилятор будет следить, чтобы туда попадали только перечисленные варианты, а редактор — подсказывать их в автодополнении. Это гораздо надёжнее «магических строк» в обычном string.

Объединение с null и undefined

Очень частый вид union — «значение или его отсутствие». В TypeScript null и undefined — самостоятельные типы, поэтому возможность «пустоты» добавляют в объединение явно: T | null или T | undefined.

Главное правило: без проверки доступно только общее

Вот ключевой момент, ради которого стоит понять union целиком. Раз в переменной string | number может лежать либо строка, либо число, компилятор не знает заранее, что именно. Поэтому он разрешает обращаться только к тому, что есть у всех членов сразу — к их общим свойствам и методам.

В терминах множеств: набор доступных операций — это пересечение возможностей всех членов. У string и number общий, например, toString() — его звать можно. А вот специфичный для строки toUpperCase() — уже нет: вдруг там сейчас число.

Обращение к значению id: string | number Доступно?
id.toString() — есть у string и у number ✅ да, метод общий
id.toUpperCase() — есть только у string ❌ нет, вдруг там число
id.toFixed(2) — есть только у number ❌ нет, вдруг там строка

Точно так же это работает и для объединения объектов: читать напрямую можно только те поля, что есть у каждого варианта.

Аналогия. Вам вручили посылку с наклейкой «внутри книга или кружка». Не вскрывая её, вы уверены лишь в общем: «у неё есть вес и размер». А вот «полистать страницы» (только у книги) или «налить чай» (только в кружку) — нельзя, пока не откроете и не посмотрите, что именно внутри.

Мостик к сужению: как добраться до специфичного

«И что, со string | number нельзя вызвать ни toUpperCase, ни toFixed?» — можно, но сперва нужно убедить компилятор, что именно сейчас в переменной. Этот процесс — «сначала проверь, потом пользуйся» — называется сужением типа (narrowing). Самый простой инструмент — проверка typeof:

Способов сужения много — typeof, сравнение с литералом, оператор in, instanceof. Все они подробно разобраны на отдельной странице Сужение типов, а для объединений объектов особенно удобны размеченные объединения.

Массивы: где стоят скобки — важно

С массивами легко ошибиться: (string | number)[] и string[] | number[] — это разные типы, и разница именно в положении скобок.

Тип Что означает ['a', 1] подходит?
(string | number)[] массив, где каждый элемент — строка или число ✅ да, элементы можно мешать
string[] | number[] весь массив — либо только строк, либо только чисел ❌ нет, это смешанный массив

Мнемоника: union действует ровно на то, к чему прилипли скобки. Прижали к элементу — (A | B)[] — гибкий разнородный массив. Обернули весь [] — A[] | B[] — «или один сорт целиком, или другой».

Второй, пожалуй, самый частый в реальном коде — функция, которая может ничего не вернуть. Тип результата T | null заставляет вызывающего проверить результат, прежде чем им пользоваться, — и это отличная защита от классической ошибки «cannot read property of null».

Обратите внимание, как union Product | null работает вместе с сужением: пока значение не проверено на null, компилятор охраняет вас; после проверки — открывает поля Product. Это и есть весь смысл объединений в одной картинке.

Коротко

  • Union A | B — «значение или типа A, или типа B»; в терминах множеств это объединение, поэтому union шире каждого члена и является их супертипом.
  • Объявляют через |: string | number, литеральные наборы ('asc' | 'desc'), много членов, псевдоним type, «пустоту» — как T | null / T | undefined.
  • Без проверки доступно только общее — свойства и методы, которые есть у всех членов (пересечение возможностей). Специфичное для одной стороны напрямую вызвать нельзя.
  • Чтобы добраться до конкретного члена, тип нужно сузить (typeof, сравнение, in, instanceof) — см. Сужение типов.
  • Массивы: (A | B)[] — разнородный массив элементов; A[] | B[] — весь массив одного сорта. Скобки решают.
